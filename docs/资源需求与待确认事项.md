# MailSec Nexus：资源与外部依赖台账

> 更新：2026-10-22。记录已确定、已有证据及尚待提供的输入；不重复打开已冻结的smart-search选择，也不把所有未知项当成立即停工原因。

## 1. 已确定/已有的基线

- 开发顺序：**smart-search → header-parser → threat-trace**；平台工程随阶段建设。
- smart-search：HTTP8080嵌套JSON为主、EML兼容、自部署ClickHouse、不要求ES DSL、当前独立运行；详见[模块决策](../mailsec-smart-search/docs/detail/待确认事项.md)。
- 公开数据已归并模块 `data/`：Enron 517,401、SpamAssassin 6,046、Nazario 3,466；下载包经校验清理，来源/哈希清单保留。数据用途限制见[算法实验](product/算法实验与质量验收.md)。
- 已有Python/FastAPI、扫描器、ClickHouse与轻量Web的独立开发验证；**不是**平台多租户、HA、正式React前端已具备。新JSON容量和真实模型评测仍待完成。
- 产品目标技术基线为React/TypeScript、FastAPI/Python、PG事务、CH检索、私有对象与持久队列；新增组件具体版本/许可证/资源按ADR验证，不直接安装一套“最新”组件。

## 3. 最小样本与交付格式

- 每批数据清单：样本ID、SHA256、来源/系统方言、采集时间、标签/依据/复核人、授权范围、脱敏版本、保留期、是否可外发。
- 原文、标签、分组/切分与实验输出分开；无原始字节时明确哪些字段只是上游声明、哪些算法不可执行。
- 正常、钓鱼、恶意附件、伪造、未知按任务分别标注；Enron不统标正常，spam不等于malware。训练/开发/测试按活动、近重复/线程和时间防泄漏。
- 附件动态分析若纳入后续范围，先提供合规样本传递方式和独立隔离基础设施；不在开发主机试运行真实恶意附件。

## 4. 版本、协议与法规边界

- 原题Python3.12沿用；PostgreSQL14.18/ES7.x作为历史兼容要求，不意味着新上线必须运行旧版本。PG14已接近2026-11-12支持结束，应选择经兼容验证的受支持生产版本；官方依据见[技术记录](product/技术依据与决策记录.md)。
- React/Vite/Node、FastAPI依赖、PG/CH、队列、扫描器、对象服务、IdP均在实施前记录兼容矩阵、安全支持周期、镜像摘要、许可证与升级策略。模型名以服务方实际接口验证为准，不仅凭原题推荐名称。
- 邮件格式/路由/认证按RFC及可信接收环境设计；法规、等级保护或行业专项要求须由项目方确认适用范围并专项评审，本文不作合规认证承诺。
- 生产SLO、RPO/RTO、保留期、检出/误报目标须在正式盲测前冻结；如环境不足，只交付明确限制的试点档，不降低安全硬门槛来宣称生产就绪。
