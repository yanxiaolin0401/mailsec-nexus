# MailSec Nexus 企业级产品综合需求分析

## 1. 产品定位与商业交付边界

### 1.1 客户、价值与成功定义

- **购买/管理方**：企业安全负责人、SOC 负责人、信息化管理员；关注数据不泄露、部署可控、可审计、分析效率和总成本。
- **日常用户**：安全分析员、响应负责人、规则/算法研究员、审计员；关注“找到邮件 → 解释风险 → 复核处置 → 沉淀规则”而不是单次模型聊天。
- **产品价值**：缩短可疑邮件调查时间；减少重复分析；用证据和反馈持续改善检出；提供可追溯的调查报告与可控规则更新。
- **业务指标**：首个可用结果时间、案件平均研判时间、人工复核工作量、告警有效率、未知/待处理积压、每千封处理成本、每案件模型成本。上线前先采集人工基线，试点后同口径比较，不预填“提升百分比”。

**主交付形态**：企业私有化部署的多租户 Web 产品，浏览器访问；同一部署内支持不同组织/项目隔离。一个企业一个独立实例是更强隔离选项，不以共享 SaaS 为前提。交付包括安装包/镜像、升级与回滚包、配置模板、运维手册、授权与许可证清单、验收报告、培训和故障处理手册。

**非首版范围**：公网商业 SaaS 自助注册/支付计费、SMTP 实时拦截网关、自动发信或封禁、攻击反制、真实人员身份归因、跨客户共享原始邮件训练、任意自然语言写操作。企业现网处置连接器及动态恶意附件沙箱是受控扩展，不能伪装成已有功能。

## 2. 用户、管理员与双模式登录

### 2.1 两类交互身份

| 身份                          | 数据与操作范围                                                                                                                                                    | 入口/限制                                                                   |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| **平台用户（user）**    | 使用所属租户内的导入、检索、研判、案件、实验等已上线功能；仅访问本人或明确共享的项目/资源                                                                         | 用户租户登录；不能访问后台、跨租户读写、管理其他账号或自行发布全平台规则    |
| **后台管理员（admin）** | **最高平台操作权限及全平台数据读写权限**，覆盖全部租户的邮件正文/附件、案件、任务、实验、规则、导出与受控删除；管理账号、租户、来源、模型、配额、配置和发布 | 管理员登录；无需租户另行授权即可管理其数据；高风险操作须重新认证/确认并审计 |

管理员的最高权限是**应用层权限**，不等于向浏览器/模型发放数据库超级用户、宿主机或任意代码执行能力。管理员可修改/删除业务数据，但必须走有版本、确认与审计的正式流程；原始证据更正另存版本，审计历史不得静默篡改。外发授权、沙箱、数据保全与危险代码发布校验仍约束所有执行路径。

### 2.2 登录页面与会话

统一 `/login` 页面明确展示 **“用户租户登录” / “管理员登录”** 两种模式：

- 用户租户登录：填写/选择租户标识并进行账号认证；服务器校验该账号属于该租户，成功进入 `/overview`。租户选择不是授权凭据，不能仅凭输入ID切换数据域。
- 管理员登录：不要求选择租户；服务器验证账号真实类型为 `admin` 并完成管理员MFA，成功进入 `/admin/overview`。后台可选择目标租户或全平台视图执行管理，不伪装成租户用户。
- 模式只决定登录流程与落地页，**不能通过URL、表单、Header或客户端role字段提升权限**。身份类型与所选模式不符时拒绝该模式登录；无有效管理员会话访问后台必须拒绝。
- 模式绑定服务端认证事务（包括OIDC state/回调校验）；两种会话具有明确用途，不共用可被前端改写的权限标记。切换登录模式须退出当前会话并重新认证，清空页面缓存/选择状态。
- 用户会话绑定经验证的活动租户；管理员会话绑定全平台管理身份，其每次租户数据操作记录实际目标租户。禁用账号/降权后立即阻止后续请求和未开始任务，不能沿用旧管理员会话。

### 2.3 用户隔离与管理员跨租户访问

- 对平台用户采用租户及资源归属/共享校验，默认拒绝；“同租户”不等于人人可读所有邮件。不同平台用户的私人任务、导出和未共享资源隔离。
- `tenant_id`由认证会话、成员关系或管理员授权路径确定；`sourceSystemId`只作来源标识，不授予租户权限。
- 列表、统计、查询、任务、对象、导出、缓存、实验和审计均执行一致作用域。管理员使用显式的后台授权路径跨租户查询/读写，而非伪造普通用户的租户参数。
- 管理员全平台统计/查询可跨租户读取；修改/删除/重跑任务须指明目标资源与租户。跨租户批操作先预览各租户影响范围，再确认，禁止隐式无范围写入。
- 用户查询范围变化、管理员切换目标租户或退出登录时清空敏感缓存。缓存键/游标包含身份类型与作用域，不能让普通用户复用管理员全局结果。
- 规则/解析器的发布和用户导出/删除申请由后台管理员审核确认；不再强制设置专门审核角色或双管理员流程。管理员直接发起高风险操作也要经过安全检查和二次确认，保留全程审计；算法实验的双人标注要求不受角色裁剪影响

## 3 明确的用户需求分析

#### 3.1 平台用户需求

平台用户的主要痛点是邮件量大、检索条件难表达、检测结果难解释、证据分散以及重复调查成本高。用户希望在一个受隔离的工作台完成调查，而非学习数据库语法或在三个工具间手动复制数据。

| 用户需求ID           | 使用场景与需求表达                                                               | 预期结果/用户验收                                                                     | 对应功能                       |
| -------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | ------------------------------ |
| UR-01 身份与数据空间 | 作为平台用户，我需要从用户租户模式登录，确认正在操作的租户及数据范围             | 登录后可见当前身份/租户；不能切换到无成员资格的租户或访问后台                         | IAM-01/02                      |
| UR-02 可靠接入       | 我需要上传EML或使用管理员分配的来源导入邮件，并知道系统是否接收、入库或失败      | 获得可追踪回执；刷新后仍可看进度，失败项有原因，不把202误认成已可检索                 | ING-01/02、EVI-01              |
| UR-03 快速定位       | 我需要按时间、收发地址、正文、附件等条件找到目标邮件，也能用自然语言表达排查问题 | 条件/时间解释可预览，结果可分页和回看；不支持的问题明确提示，不生成看似成功的错误查询 | SRC-01/02                      |
| UR-04 理解风险       | 我需要知道邮件为何可疑、哪些证据可信、哪些检查尚未完成                           | 展示模型、规则、签名各自结论和融合依据；未知、冲突、超时可区分；可提交人工标签        | DET-01/02、EVI-01              |
| UR-05 连续调查       | 我需要把相关邮件、告警和分析结果放入案件，记录调查经过并继续处理                 | 案件关联证据、任务、评论和结论；支持关闭/重开，历史不因再次分析被覆盖                 | CAS-01                         |
| UR-06 重复排查与输出 | 我需要复用查询/SOP，批量排查并申请导出可复核的调查结果                           | 可查看执行范围、预算、进度和失败项；管理员批准后仅导出批准范围，下载到期失效          | SRC-03、CAS-01                 |
| UR-07 邮件头研判     | 在S2上线后，我需要查看路由、认证和伪造/流向线索，不必手动阅读所有原始头          | 从结论定位到原始字段与可信边界；证据不足显示未知，不伪称真实攻击者                    | HDR-01、EVI-01                 |
| UR-08 行为与规则研究 | 在S3上线后，我需要从授权告警发现重复行为、创建规则候选并比较实验效果             | 有关联依据、基线/留出结果、错例及版本；可提交管理员审核，不能自行生效全平台规则       | TRC-01/02、EXP-01              |
| UR-09 操作可理解     | 我需要在桌面或手机查看关键业务，并在故障时知道是否需要重试                       | 加载/空/错误/部分结果状态清晰；重复点击不重复创建任务；模型不可用仍能结构化检索       | IAM-01、SRC-01、ING-02、OPS-01 |

UR-06中的导出/SOP为S1/P1增强，不因列为用户需求就升级为全部S1/P0；UR-07/08分别随S2/S3交付，其余具体优先级继承第5节。

#### 3.2 后台管理员需求

后台管理员需要对平台整体负责，其痛点是租户与数据分散、组件状态不透明、模型成本难控、配置变更风险大及故障后难以恢复。管理员拥有全平台最高操作和数据读写权，不受普通用户租户成员关系限制。

| 用户需求ID           | 使用场景与需求表达                                                      | 预期结果/管理员验收                                                                | 对应功能                       |
| -------------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------ |
| AR-01 统一管理入口   | 作为后台管理员，我需要通过管理员模式登录，进入全平台工作台              | 不要求选租户登录；完成真实管理员身份/MFA校验；可选全平台或目标租户视图             | IAM-01/02、ADM-01              |
| AR-02 用户与租户管理 | 我需要创建/停用租户与账号、分配用户归属，并管理来源和服务凭据           | 仅有user/admin两类身份；禁用/降权/密钥撤销后旧访问失效，变更有记录                 | IAM-02、ING-02、ADM-01         |
| AR-03 全平台数据管理 | 我需要跨租户查看邮件正文/附件、案件、任务与实验，并执行修改、导出或删除 | 无需租户另行授权；写操作明确目标，批操作有影响预览，修改/删除保留版本或处置审计    | EVI-01、CAS-01、ADM-01         |
| AR-04 策略与资源调控 | 我需要配置模型、外发字段、检测器、配额、留存和模块开关，控制费用及负载  | 配置先校验再生效，有版本和回退；密钥不可回显；额度耗尽、模型失败有明确降级         | DET-02、ADM-01/02              |
| AR-05 发布与申请处理 | 我需要审核用户导出/删除申请和解析器/规则候选，控制生效范围              | 可查看评测、影响范围与失败项；不合格版本不能发布；管理员直接操作也需安全校验与确认 | SRC-03、HDR-02、TRC-02、ADM-01 |
| AR-06 运行与恢复     | 我需要发现积压/异常、定位失败、重试或取消任务，并完成升级和恢复         | 从告警关联到任务/依赖；已接收数据可对账；备份可实际恢复，发布可按既定边界回滚      | ING-02、ADM-02、OPS-01         |
| AR-07 可追溯监督     | 我需要知道谁在何时对哪些数据/配置执行了什么操作及其结果                 | 审计可检索并关联版本/请求/任务；跨租户操作记录实际范围，历史不可静默篡改           | EVI-01、ADM-02、OPS-01         |

#### 3.3 用户需求的确认与取舍

- 以两个真实账号类型的端到端任务验收，不以“页面存在/接口返回200”替代任务完成。用户越权拒绝和管理员授权跨租户操作成功必须同时验证。
- 试点前记录人工检索/调查耗时、重复操作、误报处理量与每次分析成本；试点后同任务比较。改善比例须实测后确定，不提前承诺。
- 任何页面结果都应回答“数据范围是什么、完成到哪一步、依据是什么、下一步能做什么”；不确定性是必要输出，不强制所有请求得到正常/恶意二选一。
- 账号自助注册/支付、SMTP拦截、自动封禁和未授权外发不因用户希望“一键处理”而进入当前范围；新增需求走范围与安全评审。

## 4. 端到端业务流程与状态

| 流程                | 正常闭环                                                                                            | 异常/控制点                                                                |
| ------------------- | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| W0 租户开通         | 后台管理员建租户/用户 → 分配归属与配额/留存 → 建项目/来源 → 用户租户登录及合成邮件验收           | 外发默认关闭；来源未绑定不得接入；资源不足不能假成功                       |
| W1 数据接入         | JSON/EML/批量 → 授权/限额 → 原始证据与接收回执持久化 → 异步清洗/索引 → 对账                     | 202 是持久接收非已索引；重复/冲突分别处理；错误可定位、重试、死信处理      |
| W2 检索研判         | 条件或 NL → 可读计划预览 → 安全查询 → 邮件详情 → 按需检测/模型 → 证据解释 → 人工复核          | 模型失败不影响结构化检索；无原始附件字节不可宣称已扫毒；未知不等于安全     |
| W3 调查处置         | 可疑邮件/告警 → 建案件 → 分派 → 关联证据/时间线 → 研判 → 建议 → 人工确认处置记录 → 关闭/重开 | 首版“处置”是复核、标注、报告和线下处置留痕，不伪称已隔离企业邮箱中的邮件 |
| W4 解析器演进（S2） | 异常头样本 → 方言归因 → 候选解析代码/测试 → 隔离回放 → 评测/审核 → 灰度/回滚                   | 线上解析确定性执行；候选代码不接生产凭据；新版本不覆盖旧证据               |
| W5 规则运营（S3）   | 告警/案件 → 行为聚类 → 候选规则 → 留出回测 → 后台管理员审核确认 → 影子运行/启用 → 命中回流    | 规则有效范围/版本明确；未通过回测不发布；暂停和回滚可追踪                  |
| W6 生命周期         | 留存到期或批准删除 → 检查保全 → 即时逻辑不可见 → 索引/对象/缓存删除 → 对账回执                  | 备份按约定期限过期；恢复后重放删除台账；法律保全冲突须审批                 |

**状态必须分层**：

- 接入作业：`accepted → queued → running → succeeded / partial / failed / cancelled`，重试是新 attempt，保留原因；已持久接收后禁止静默丢弃。
- 邮件：证据可用性、解析完整性、索引状态、各引擎状态彼此独立。
- 风险：`unknown / clean / suspicious / malicious`；人工决定与模型/规则结论并存；clean 是指定策略和证据范围内的结果，不是绝对安全保证。
- 案件：`open → triaged → investigating → pending_review → resolved → closed`，退回/重开带理由。
- 规则/解析器：`draft → evaluating → pending_review → approved → shadow → active → retired`，失败/拒绝另记；回滚指向已审核的版本。

| HDR-01 | S2/P0       | 多方言确定性解析、有序头、可信路由、认证来源、伪造/流向                      | 各方言分层评测，未知单列，可信边界可解释                          |
| HDR-02 | S2/P0       | 模型辅助候选解析器、隔离测试、历史反验、发布与回滚                           | 沙箱拒绝越权；旧版可复现；灰度失败可回退                          |
| TRC-01 | S3/P0       | 外部告警导入、邮件关联、行为聚类与可解释时间线/关系图                        | 原始来源保留；关联置信/未匹配可见，不冒认攻击者                   |
| TRC-02 | S3/P0       | 候选检出算法/规则、版本化回测、反例、审批/影子/生效/回滚                     | 留出集实验、执行资源上限、管理员审核确认与命中回流                |
| EXP-01 | 各阶段/P0   | 数据集/标签/切分/实验登记、指标、错例、模型/算法版本                         | 固定清单可复跑；开发/测试不混用；真实与 mock 分开                 |
| ADM-01 | S1/P0       | 统一后台管理租户/用户/来源/留存/配额、全平台数据、模型策略、检测器与模块开关 | 所有配置有范围、版本、校验、审计；高风险需复核                    |

| 功能单元           | 主要责任方                                          | 主要使用者                   | 输入 → 输出                                                  | 对应需求/阶段               |
| ------------------ | --------------------------------------------------- | ---------------------------- | ------------------------------------------------------------- | --------------------------- |
| 登录与身份授权     | mailsec-platform                                    | 平台用户、后台管理员         | 账号认证/登录模式/租户 → 可信会话与访问范围                  | IAM-01/02；S1               |
| 接入、任务与证据   | smart-search负责接入清洗，平台负责统一任务/证据访问 | 用户提交、管理员管理         | JSON/EML/来源凭据 → 回执、原文引用、质量/索引状态            | ING-01/02、EVI-01；S1       |
| 邮件智能检索与研判 | mailsec-smart-search                                | 平台用户、后台管理员         | 条件/NL/邮件/分析请求 → 查询结果、检测证据、融合意见/SOP报告 | SRC-01/02/03、DET-01/02；S1 |
| 异构邮件头解析     | mailsec-header-parser                               | 用户查看/研究、管理员发布    | 有序头/可信配置/方言样本 → 路由/认证/伪造/流向与解析器版本   | HDR-01/02；S2               |

### 5.3 登录与身份授权功能

- 提供第3.2节的双模式登录、退出、过期处理和用户租户校验；维护用户账号类型/状态及可访问资源，不新增第三种交互角色。
- 后台管理员管理账号与租户归属；来源凭据独立签发、绑定作用域并支持撤销/轮换。
- 对页面、API、后台任务、下载和缓存执行同一授权语义；管理员全平台读写走受信后台路径，不靠客户端切换模式授权。
- **输出/异常**：成功创建明确身份和作用域的会话；错误模式、错误租户、过期/停用身份必须拒绝，不回退为高权限账号。
- **验收**：用户正常登录/租户隔离，管理员登录/跨租户读写，伪造参数拒绝，退出/降权后旧会话失效。

### 5.4 接入、任务与证据管理功能

- 管理员配置来源与配额；用户经授权提交JSON、EML或批导。兼容既有字段、入口及EML/JSON不同去重语义。
- 接收前检查身份、格式、大小及限额；持久保存后返回回执，异步完成清洗、解析和索引。原文、质量异常、各处理阶段分别存证。
- 提供任务状态、逐条失败原因、有限重试、取消和死信处理；管理员可全平台管理，用户只查本人/共享范围。
- 提供证据受控查看、哈希核验、版本、保全和删除对账；无原始字节时明确缺失，不能据元数据伪造原文/扫描证据。
- **输出/异常**：返回稳定事件/任务标识；同来源键同载荷幂等，同键不同载荷409；超限拒绝，部分失败逐条列出。
- **验收**：接收→索引→检索可追踪；中途重启后无静默丢失或多计；原件引用可核验，删除/恢复遵守生命周期。

### 5.5 smart-search：智能检索与风险研判功能

- **结构化检索**：按模块已支持字段进行组合筛选、统计、稳定分页和详情查询；完整字段参与匹配，摘要截断不影响查询正确性。收藏/共享遵守资源范围。
- **自然语言查询**：识别时间与实体、生成受限计划并预览；执行前验证字段、参数、身份和预算，服务端编译参数化查询；不执行自由SQL。
- **邮件研判**：分别记录本机检测和独立模型意见，再进行证据感知融合；展示证据、冲突、未知、引擎/模型/策略版本和人工反馈。
- **模型与SOP**：适配既定双协议，按授权调用最小字段；SOP按条件初筛、有限批量研判并输出报告，记录额度和失败。导出/SOP增强保留P1优先级。
- **输出/异常**：查询结果/计划、风险与证据、分析历史/报告。模型超时不阻断结构化查询；JSON缺附件字节时不执行或宣称完成附件扫描。
- **验收**：同一授权查询的列表、数量和详情一致；NL结果正确且无法越权；算法/模型/融合分别有同集评测，未知不计作安全。

### 5.6 header-parser：邮件头解析与演进功能

- 接收原始有序头/邮件和可信接收配置，识别方言、提取路由/认证字段、保留重复与异常；输出字段证据定位。
- 结合信任边界分析首跳候选、身份关系、伪造线索和流向；四码定义未取得或证据不足时返回未知，不猜测业务含义。
- 建立异常采样→模型辅助候选代码/测试→隔离回放/性能验证→管理员审核→版本发布/回滚的演进流程；生产解析路径确定性运行。
- **输出/异常**：版本化解析和路由/风险证据、错误类型及候选产物；失败保留smart-search基础结果，不拖垮已上线检索。
- **验收**：各方言、伪造、流向和未知分别统计；畸形/最坏耗时有报告；候选未验证不得执行于生产，旧版本可回放。

### 5.7 threat-trace：行为分析与规则运营功能

- 导入情报检出的告警、保留来源和标签，与授权邮件/证据关联；未匹配、歧义和关联置信度可见。
- 归纳相似行为与反例，形成可解释的行为簇/时间线和候选检测算法/规则；关系图是解释入口，不代替算法产物。
- 支持冻结数据回测、基线对比、错例审阅和版本管理；管理员审核后按明确范围影子运行、生效、暂停/回滚。
- 将规则命中按邮件/告警标识反馈至检索和案件；用户不能自行扩大生效范围，管理员跨租户发布须确认范围并审计。
- **输出/异常**：行为证据、候选规则及说明、实验结果和命中记录；超时/部分回测不可标完整通过。
- **验收**：从告警到规则命中反馈形成闭环；独立留出和跨活动/时间泛化结果可复算，不把有限集100%外推为未来保证。

### 5.8 案件、实验与报告功能

- **案件**：创建/指派、关联邮件/告警/分析、评论、标签、复核、关闭/重开；保留每次状态变更和证据引用，不提供未接入的在线拦截/封禁假动作。
- **实验**：登记来源/授权/标签版本、固定切分、算法/模型/提示词/环境和参数；执行可追踪任务，汇总指标、错误、未知、耗时与费用。
- **报告**：展示数据范围、结论/依据、版本和完整性；导出按管理员确认范围生成并限期访问，不能通过报告旁路读取其他用户数据。
- **输出/异常**：案件历史、实验记录、可复核报告；证据被删除/不可用时显式标记，报告/实验不得保留未授权下载入口。
- **验收**：从检索到案件结案可完成；同清单/版本的确定性算法实验可复跑，外部模型重复性限制单列；结果链接重新鉴权。

### 5.9 后台管理与系统运行功能

- 提供租户/用户/来源管理、全平台数据查询与读写、任务调度、模型/检测策略、配额/留存、模块开关、规则/解析器发布和审计查询。
- 配置变更具备校验、影响预览、版本和回退；高风险操作二次确认，账号类型变更/撤销立即使旧权限失效。
- 展示组件健康、队列积压、索引新鲜度、查询/模型失败、资源和成本；提供故障定位、重试及维护状态，不能只展示静态健康图标。
- 通过受控运维流程完成部署、升级、备份恢复与回滚；不要求将任意Shell/数据库超级权限暴露成后台按钮。
- **输出/异常**：管理回执、配置版本、审计、告警和恢复记录；审计无法持久化时拒绝高风险操作，管理失败不静默提交半套配置。
- **验收**：管理员可管理全部租户数据，用户不可进入后台；管理动作可追溯；实际恢复与发布演练满足第9节冻结的质量要求。

### 5.10 模块联动与阶段验收

S1只启用已实现的接入/检索/研判和平台基础流程；S2以同一事件/证据引用增加头部分析；S3追加告警、行为和规则结果。模块间交换版本化契约，不直接改写其他模块私有表。每次接入新模块都复跑既有功能、权限和故障降级用例；未上线模块不显示可执行空入口。详见第4节状态机及第7节数据边界。

## 6. 工程架构要求

采用 **独立 SPA 前端 + 平台 API/BFF + 领域模块/独立 Worker + 数据基础设施**。初期采用可拆分的模块化后端，不为展示“微服务”引入不必要服务网格；重解析、扫描、模型和回测因风险/资源不同单独执行。租户、任务、案件、审计、模型策略属于平台共享能力，不在三个模块重复建设。

| 层        | 产品技术基线（待实现部分不是已安装声明）                               | 决策目的                                                    |
| --------- | ---------------------------------------------------------------------- | ----------------------------------------------------------- |
| Web       | React + TypeScript + Vite；企业组件库 Ant Design；路由与服务端状态缓存 | 响应式控制台、表格/表单/权限交互；不用 API 文档替代产品页面 |
| API/算法  | Python 3.12、FastAPI/Pydantic、OpenAPI；Python 核心算法包              | 复用现有能力，前后端契约生成与校验                          |
| 事务库    | PostgreSQL + 迁移工具；应用授权 + RLS 防御                             | 用户/项目、任务、案件、审核、策略、实验元数据与 outbox      |
| 检索分析  | ClickHouse；按租户/时间/查询模式实测设计                               | 邮件检索、聚合和分析投影；不承担身份/审批事务               |
| 证据      | 支持 S3 API 的私有对象存储；加密、版本/保全与生命周期能力按选型验证    | 大对象/附件/报告，不塞事务表、不暴露公共桶                  |
| 任务      | 生产基线持久消息队列 RabbitMQ + 独立 Python Worker；事务 outbox        | 重试、死信、可追溯投递；不宣称 exactly-once                 |
| 身份/流量 | 企业 OIDC（可独立部署身份服务）、反向代理/TLS                          | 后端会话与租户授权；只让入口面向用户网络                    |
| 安全/观测 | Rspamd、ClamAV、隔离执行池；OpenTelemetry、指标/日志/告警              | 证据化检测、资源边界、运维可见性                            |

**选型约束**：组件具体兼容版本/镜像摘要在实现阶段锁定，建立 SBOM 与许可证清单；不使用浮动 latest。原题 PostgreSQL 14.18 / ES 7.x 是兼容/历史数据要求，不能未经支持周期审核就作为新生产部署版本；ES 只在 S2 需要读历史日志时提供只读适配器，不变成 smart-search 必装检索引擎。Kafka、Redis、向量数据库、Kubernetes 均非为了“企业级”默认全部引入。详见[架构设计](../mailsec-platform/docs/architecture.md)。

## 7. 数据与接口要求

1. 区分租户/项目、投递事件 `event_id`、内容对象 `content_sha256`、原报文 `Message-ID` 和来源键；同内容重复投递可为多个事件，群发多个收件人不拆多个事件。当前旧 EML 内容去重与 JSON 投递幂等各自保留。
2. 原始证据、规范化字段、查询投影、模型推断、人工标注和规则版本分别保存；缺失字段占位不能掩盖 `unknown` 或证据缺失。
3. 对外业务 API 版本化；长任务返回回执和查询入口；同步响应有请求 ID、错误类别、权限及限额反馈。模型不接数据库自由 SQL 或生产写权限。
4. PostgreSQL 是流程状态权威；ClickHouse 是可重建投影；对象存储是原始证据权威。显式处理跨存储非原子、索引延迟、重复投递和删除传播。
5. 升级前为既有单租户数据指定受控 legacy 租户/项目并核对归属，不能从不可信来源字段自动推断。新租户不得看到迁移未归属数据。

## 8. 算法要求：不止接入模型 API

至少形成可独立评测且集成在产品里的核心算法资产：

| 算法                  | 输入 → 输出                                                       | 技术难点/生产入口                                                            |
| --------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| A1 受约束 NL2Query    | 自然语言、允许字段与授权上下文 → 类型化过滤/统计计划、解释        | 实体占位恢复、时间语义、逻辑约束、结果一致性；进入检索页，不直接执行生成 SQL |
| A2 证据感知风险融合   | 独立模型意见、规则/签名信号、证据质量 → 风险/未知、证据、复核建议 | 缺失/冲突处理、概率校准与阈值、可解释拒判；进入研判和案件                    |
| A3 可信边界头部解析   | 有序原始头、可信接收配置 → 路由候选图、认证来源、伪造/流向        | 方言、伪造链、正则最坏复杂度、缺失证据；进入详情和解析器版本管理             |
| A4 行为模式与规则挖掘 | 带证据告警/标签 → 行为簇、候选规则、回测与反例                    | 去重/跨活动泛化、可执行规则约束、低误报；进入规则实验与审批                  |

每项必须交付问题定义、预处理、算法实现、基线、消融、冻结留出集、可重跑命令、资源/成本、错例和改进记录。A2 的受控策略基线可先行，再用实证比较可训练融合；不能将“多个引擎投票”本身当作有效性证据。算法实验要求见[算法与验收](product/算法实验与质量验收.md)。

## 9. 非功能需求、生产就绪与质量门禁

### 9.1 非功能需求总表

| ID                | 必须满足的要求                                                    | 验证边界                                                                        |
| ----------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| NFR-01 安全隔离   | 身份、资源、对象、缓存、任务全链隔离；高风险动作最小权限与复核    | 授权测试集零越权；不据此声称不存在未知漏洞                                      |

### 9.2 性能与容量需求（NFR-02）

以下数值沿用[交付路线图](product/工程交付与实施路线图.md)的**建议验收目标**，不是当前实测或已签SLA；硬件/副本、邮件大小、语言、保留期和查询混合在正式压测前冻结，两个文档须同步维护。

| 指标       | 建议目标                                              | 条件与测量方法                                                                           |
| ---------- | ----------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 接入容量   | 规划10万封/日；暂按约12条/秒测试峰值                  | JSON/EML分别报告；持续24小时并统计接收、成功、失败、在途和死信，不用批导吞吐替代HTTP峰值 |
| 结构化查询 | P95≤2秒，P99≤5秒                                    | 约300万事件、20并发用户混合读；固定查询集、冷热缓存分组，包含排队时间                    |
| 正文检索   | P95≤5秒，P99≤10秒                                   | 明确语言、关键词/短语和时间窗；同时报告扫描量、超时/拒绝，不剔除失败请求美化分位数       |
| JSON回执   | P95≤1秒                                              | ≤256KiB合法载荷、约12条/秒暂定峰值；计时包含持久接收，EML按大小分组另测                 |
| 索引新鲜度 | 正常负载P95≤10秒、P99≤30秒                          | 从accepted至可检索；故障积压及排空时间另报                                               |
| 资源稳定性 | 24小时混合负载无OOM/失控积压；合法请求系统错误率<0.1% | 记录CPU/内存/磁盘/队列峰值；限流和超时单列，不能作为正常结果                             |

列表服务端分页，导出/回测等长任务异步执行。按租户/任务设并发、扫描、内存、结果量和模型费用上限；管理员拥有数据权限不等于无限资源预算。

### 9.3 可靠性、可用性与恢复需求（NFR-03）

- **持久性**：返回202后，普通进程重启/短暂网络故障下任务与原始证据可恢复；通过发布确认、幂等处理和对账防静默丢失，不承诺消息恰好投递一次。
- **容错**：单条坏样本、模型超时或一个增强模块故障不得拖垮基础检索；重试有上限，永久错误转失败/死信，向用户说明影响范围。
- **可用性**：HA档月度≥99.9%为建议目标，计入约定核心API的有效请求超时和依赖故障；单机开发/试点不据此宣称HA，短期测试不替代月度观测。
- **灾备**：暂定RPO≤15分钟、RTO≤4小时，恢复范围含证据、状态、密钥恢复材料、投影与删除台账；实际恢复并按租户对账后判定，备份文件存在不算通过。
- **一致性**：页面区分已接收/待索引/部分完成；取消、重试和恢复不伪造全部成功，已发生副作用保留记录。灾难RPO窗口与普通重启不丢失要求分别解释。

### 9.4 安全性、隔离与隐私需求（NFR-01/05）

- **权限**：用户数据按租户/归属/共享隔离；管理员可全平台读写但必须经真实管理会话。双模式登录、API、队列、游标、缓存、下载和导出均验证主体与作用域。
- **身份安全**：管理员MFA、会话过期/退出/撤销、登录失败限制及CSRF防护；修改客户端mode/role、租户ID或回调参数不得产生管理员权限。
- **数据保护**：跨主机访问使用TLS，敏感存储与备份加密，密钥不入代码/日志或回显；原文下载与数据外发分别授权，默认不向第三方发送未授权数据。
- **不可信内容**：邮件HTML/附件默认不执行；解析/展开/正则/扫描有界；候选代码走隔离测试，动态附件执行不在本期静态扫描能力中冒充实现。
- **模型与工具**：邮件不得成为系统指令；工具执行验证白名单、参数、权限和预算，阻止任意SQL/Shell/URL及SSRF；脱敏失败或授权撤销时停止外发。
- **证据与审计**：管理员业务写操作也保留版本/处置记录；保全、删除、缓存和备份恢复一致处理，审计不可静默篡改。
- **验收**：权限与注入负测集中危险执行/越权成功数为0，管理员合法跨租户操作正测通过；未修复可利用严重/高危问题不得上线。此门禁不代表不存在未知漏洞。

### 9.5 易用性、响应式与无障碍需求（NFR-04）

- 用户租户/管理员登录模式清晰，身份与当前操作范围始终可见；导航只显示已上线且可访问的功能，关键路径在统一平台内完成。
- 桌面/平板/手机目标视口1440/1024/768/375px；核心检索、详情、任务/案件可操作，无意外页面级横向溢出，复杂表格在明确容器内滚动。
- 页面具备加载、空、错误、无权限、部分结果及过期状态；任务可刷新续查，失败给出原因/恢复路径，危险操作展示影响后确认。
- 指定网络下主要交互页LCP P75≤2.5秒为建议目标；测试生产构建、冷启动/缓存两组，不以开发服务器体验代替上线性能。
- 支持键盘、焦点、标签和非纯颜色风险提示；按既定WCAG 2.2 AA目标结合自动与人工验收。浏览器验收矩阵至少覆盖约定的Chrome/Edge桌面及移动浏览器，具体版本随发布冻结。

### 9.6 可维护性、兼容性与扩展性需求（NFR-06）

- **模块可维护**：领域算法与平台控制面分离，独立单测/版本/发布；新模块通过契约接入，不破坏smart-search自主运行。
- **接口与数据兼容**：保留已有JSON/EML协议及幂等含义；Schema/API有版本，新增字段/枚举、存量迁移、弃用和回滚均有测试，不静默改变风险/时间/身份语义。
- **质量保障**：CI独立执行lint、类型检查、单元/集成/契约/E2E与安全扫描；每个失败如实列出，历史部分检查通过不能代替全仓通过。
- **可扩展**：模型适配、方言解析器、规则/扫描器使用明确接口；Worker可按任务类型扩容，限流/幂等不能只依赖单进程内存。引入新存储/服务须有负载或功能依据。
- **验收**：新模块/适配器加入后旧协议回归通过；锁定版本可重建；迁移和回滚演练保留数据一致性证据。扩容收益须实测，不承诺线性增长。

### 9.7 可观测性、运维与交付需求（NFR-07/08）

- HTTP、队列、解析、扫描、模型和查询用request/trace/job ID关联；监测接收/索引延迟、积压/死信、超时、资源、模型用量及成本，并能定位至阶段/版本。
- 运行日志与审计分层，默认不记录正文、密钥或完整敏感查询；管理员跨租户读写、配置/权限变更、导出/删除和发布必须记录实际范围及结果。
- 告警定义级别、阈值、责任人和恢复手册；部署具备健康检查、启动/停机、资源限制和密钥配置，前端产物/API/数据迁移可成套发布。
- 交付包含需求/设计、接口、数据库迁移、测试/实验报告、SBOM/许可证、安装/升级/回滚、备份恢复和用户/运维手册；每个发布版本注明功能与环境限制。
- 新环境全栈部署、浏览器关键旅程、故障恢复和回滚实际演练通过才签收对应档位；未拿到生产环境/真实模型/企业数据时只能报告相应验证版范围。

### 9.8 算法质量与验收可追溯性

算法功能是否存在与算法是否有效分别验收：第8节的A1—A4均需问题定义、固定输入输出、基线/消融、冻结留出集、错误/未知分母及运行成本。NL语义一致率建议目标≥95%；原题头部/流向99%和规则100%按各自冻结口径解释，不转换为全场景保证。模型不可用、扫描超限和无证据不能计为安全样本。

用户需求UR/AR → 第5节功能ID → 对应模块/API/页面 → 第9节NFR → 测试或实验报告构成追踪链。数值目标调整须记录环境、理由与确认结果，不得在观察测试结果后单方降低门槛；未通过项进入缺陷/风险台账，不能通过文档标记为已完成。
