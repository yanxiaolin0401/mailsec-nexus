# 核心算法、实验设计与质量验收

> v1.0 草案 · 不是实验完成报告。历史实测见 [smart-search 验证记录](../../mailsec-smart-search/docs/验证记录.md)。目标是证明算法真正支撑产品，而非只展示模型文字回答。

## 1. 通用实验协议

1. **定义任务和真值**：区分垃圾邮件、钓鱼、恶意附件、身份伪造、流向和未知；不同任务分别定义正负标签，不能把 spam、phishing、malware 混为同一标签。
2. **数据合法性**：记录来源/许可、脱敏、允许用途与外发授权。公开可下载不等于可商用重分发，也不等于允许全量送第三方模型。企业数据隔离，研究使用须单独批准。
3. **清洗与切分**：先按内容哈希/近重复线程/活动/来源分组去重，再按时间/活动划分训练、调参、冻结测试；同一活动的模板变体不能随机分散产生泄漏。比例按稀有类别规模冻结，不能以比例替代足够样本。
4. **标注**：说明指南与证据，至少关键测试集双人独立标注、分歧仲裁；记录一致性。模型预测、现有规则结果、文件夹名称都不能未经复核当最终真值。
5. **复现**：保存样本清单哈希、分组/切分、代码/镜像/依赖、parser/rule/model/prompt/policy 版本、参数、随机种子、硬件与计时范围。外部模型非完全确定性时保存授权输出并重复测量，不保证任意日期精确重放。
6. **统一比较**：基线、改进、消融使用同一冻结集、相同预算和预处理；模型看到的输入不包含待比较检测器的判定，保留独立性，融合再使用各路输出。
7. **完整报告**：包括未知、失败、超时、截断、配额拒绝、模型成本、吞吐和延迟，不删除难例后计算“准确率”；报告宏/微平均及各来源/类别切片。
8. **实验发布**：开发集调阈值，测试集只验收；看过测试错例后再调参则须声明测试集已用于开发并另取封闭留出集。审核结果反馈到下一版训练/开发，不污染当前验收。

## 2. A1：受约束自然语言检索算法（S1）

**问题**：将自然语言调查意图映射为可授权、资源有界且语义正确的查询，而不是生成看似合理的 SQL。

- 输入：问题、时间锚点/时区、允许字段字典、合法枚举、可用工具能力；敏感实体本地占位。不向模型发送凭据/任意全库数据。
- 输出：版本化 QueryPlan（filter AST、时间范围、排序、投影、聚合、limit）、可读解释、拒绝/需澄清原因；租户/项目由服务端强制绑定。
- 实现：本地实体识别/占位 → 模型受约束计划 → Schema/类型/逻辑/字段授权验证 → 实体绑定/时间标准化 → 确定性参数化模板编译 → 预算与权限校验 → 预览/执行。
- 基线：固定关键词/模板规则；模型直接结构化输出（仅在隔离评测，不把自由 SQL 作为生产执行基线）。
- 改进/消融：去掉时间锚点、实体占位、字段约束、后校验分别测；比较提示模板/模型版本，统计改进是否只靠更多调用成本。
- 集成：检索页面的计划预览、执行与错误解释，查询审计中记录计划哈希和版本，不记录敏感明文。

**数据/指标**：建设建议不少于300条开发问题与200条冻结测试问题，覆盖多条件、否定/逻辑组合、相对周/月、中文实体、歧义、不支持部门映射、越权、注入、高成本查询；最小数量是设计建议，不是已有数据。指标：计划合法率、过滤条件语义准确率、结果集一致率、可回答覆盖率、正确拒绝率、越权/危险执行通过数、P95 与单次成本。固定数据库快照计算结果集一致，不以语法通过代替语义正确。

## 3. A2：证据感知的邮件风险融合（S1 核心）

**问题**：面对模型、规则/签名、数据缺失和引擎失败，输出可解释且可拒判的风险；不能以多数票消除证据不足。

- 输入：EML 或 JSON 规范字段/证据可用性；Rspamd 分数/符号，ClamAV 签名/启发式/限额状态，独立模型结构化结论与证据，解析质量、版本。
- 输出：`verdict, evidence_refs, reason_codes, evidence_quality, review_required`；如输出概率必须经校准并说明适用集，模型口头置信度不直接当真实概率。
- EML 与 JSON 分轨：有原件才实际扫描；只有 JSON 元数据的样本标记扫描 unavailable，不补零分、不给 clean 票。
- 基线 B0：单独 Rspamd / ClamAV / LLM（按适用任务分别测）；B1：当前保守规则融合与拒判；候选 B2：基于规则符号、校准分数、缺失指示和证据质量的逻辑回归/树模型晚期融合，之后开发集概率校准与成本敏感阈值。
- B2 是待实验方案，不预先宣布优于 B1；禁止用任意未经验证权重“凭经验加权”后声称最佳。无足够标签时保留 B1，不用伪标签冒充监督真值。
- 决策：明确恶意签名独立记录；模型/规则冲突、解析截断、未扫描附件或引擎错误按策略拒判/待复核，不把总分低当安全。
- 改进实验：有无缺失特征、有无校准、有无拒判、单路/多路、不同阈值、不同输入长度；统计召回增益与误报/人工工作量/费用的权衡。

**指标**：各类 precision/recall/F1、FPR、PR-AUC（有连续分数时）、覆盖率/拒判率、已判定风险与全样本端到端漏检、混淆矩阵、模型费用、耗时/内存。置信区间按活动/来源分组 bootstrap 或适合的二项区间说明方法；多模型/多种子重复报告方差。

**上线策略**：影子模式先收集证据，不自动封禁/删除；人工复核与版本化标签闭环。只有同集对比显示真实改进且安全门禁通过才升级融合策略；监测来源/类别分布漂移、误报、拒判和成本，必要时回滚。

## 4. A3：可信边界驱动的头部解析与流向（S2 核心）

- 输入：保序多值 Header、原始字节定位、方言/系统版本、可信接收网关/域/`authserv-id` 配置、可用信封信息；历史 DNS/认证证据可缺。
- 输出：规范字段、Received 跳点/边、时间约束与异常、最早可信可证候选节点、认证“声明/可信观测/重新验证”分类、伪造线索、流向编码或未知、证据引用。
- 算法：确定性词法/有界语法解析 → 厂商方言插件 → 路由图与时间/身份一致性约束 → 从可信接收边界向外验证 → 证据缺失拒判。不能把任意最下方 Received 当真实首跳。
- 模型使用：离线聚类未知方言、解释失败、生成候选解析器/测试；沙箱静态审查、单测、模糊/最坏复杂度测试、历史回放、审核发布后才上线。生产热路径不在线生成代码。
- 基线：标准邮件库字段提取、通用规则解析；改进比较方言插件、信任边界、时间一致性、有无异常拒判。
- 数据：Coremail/Exchange/Postfix/O365 分层样本，含真实正常/转发/伪造和合成畸形；合成集只证明边界处理，不能代替真实方言准确率。
- 指标：字段级 precision/recall/F1，路由节点/边准确性，伪造二分类，四流向 macro-F1/混淆矩阵/准确率，未知率，各方言最差表现，单条最坏时长/超时率、吞吐与内存。
- 发布入口：详情证据页、解析研究台、版本审核/灰度；失效版本可回滚且原结果仍可重现。

**原题99%**：伪造和流向分别定义标签、分母、置信区间和完整样本覆盖；证据不足的 unknown 必须单列并计入覆盖，不只在“容易的可判样本”上报99%。生产可用性99%是服务指标，不能用解析成功率替代。四码正式定义缺失时不得私自映射。

## 5. A4：行为关联与候选检测规则挖掘（S3 核心）

- 输入：**情报检出的告警**及来源、关联邮件/解析特征、时间、授权标签与反例；仅原始邮件不能替代原题告警输入。
- 输出：有支持/冲突证据的行为簇/时间线、可执行且资源有界的规则/算法版本、适用范围、训练/留出回测与说明。图谱只是解释方式，不是唯一产物。
- 算法候选：时间/域名/URL/附件/路由/模板相似度的归一化特征 → 倒排候选生成避免全量 O(n²) → 可解释相似图/聚类 → 频繁特征组合或受限决策规则挖掘 → 负样本剪枝/复杂度惩罚 → 独立留出验证。
- 模型作用：归纳簇内语义、给候选规则及解释；规则 DSL/AST 白名单编译，限制正则/步数/扫描时间。必须生成 Python 算法时走与解析器相同的隔离评测和审核，不热执行模型代码。
- 基线：人工静态规则/单 IOC 匹配；消融比较文本语义、时间、头部/附件、反例剪枝，分析“模型仅改写 IOC”是否真有泛化。
- 指标：关联/聚类质量（有簇真值时用 pairwise-F1/ARI 等）、规则 precision/recall/FPR、每百万正常事件误报数、覆盖率、跨活动/时间/来源效果、规则复杂度、每千封耗时、生成/审核成本。
- 产品闭环：行为簇 → 实验 → 反例审阅 → 审批 → 影子模式 → 生效 → 命中回流检索/案件 → 漂移与回滚。用户候选规则限制在所属租户；后台管理员可显式选定单租户、多租户或全平台生效范围，记录影响预览、确认与审计；共享样本/解释须脱敏，不因管理员发布而泄露其他租户数据。

**原题100%**：记录企业最终解释的是 accuracy 还是 precision，并同时报告其他指标。有限冻结集可出现100%，不代表未来全场景零误报；零观测误报仍须置信上界，不能隐藏样本量/低覆盖率。原题模型名称只作来源记录，实际可用模型标识须验证。

## 7. 量化验收建议（待试点基线冻结，不是既得结果）

| 算法门禁 | 拟议标准 | 说明 |
| --- | --- | --- |
| NL 语义 | 支持范围内冻结问题结果集一致率 ≥95%；不支持问题拒绝/澄清单列 | 分母与问题分类冻结；不能只报告合法 JSON 比例 |
| 工具安全 | 测试集中越权、任意 SQL/shell、跨域读取的实际执行数为0 | 安全阻断门禁，不承诺数学上无漏洞 |
| 融合有效性 | 与冻结基线同集比较，至少一个预先选定主指标改善且 FPR/成本不突破批准预算 | 主指标/最小增益/置信区间在看测试集前冻结；当前基线不等于合格 |
| 头部/流向 | 按原题99%分别验收，并报告 unknown 与各方言指标 | 先获得定义/样本；未达到则报告差距不能调整分母 |
| 规则泛化 | 原题100%目标在冻结集具体口径验证，另报跨时间/活动效果 | 不能仅 IOC 重放命中冒充泛化 |
| 工程集成 | 算法在真实 API/Worker/页面闭环调用，实验版本与上线版本一致可追踪 | 离线 notebook 成功不等于集成完成 |

## 8. 软件测试矩阵

| 层 | 覆盖重点 | 必需证据 |
| --- | --- | --- |
| 单元/属性/模糊 | Schema、解析、时间、幂等、状态机、算法边界、恶意输入 | fixtures、随机种子、失败最小样本/回归 |
| 集成/契约 | PG/CH/对象/队列、双模型协议、扫描器、跨模块版本 | 真实依赖测试与 mock 分开；契约破坏阻断CI |
| 前端/全栈 | 登录、租户切换、导入、检索、详情、案件、审批、移动端 | 生产构建的浏览器E2E、截图、无未处理 JS 错误 |
| 安全 | IDOR、RLS池复用、对象下载、权限撤销、CSRF/XSS/SSRF、注入、沙箱越界 | 自动拒绝测试、人工复核、可追踪整改；凭据不入报告 |
| 负载/稳定 | JSON/EML各自压测、混合负载、冷热缓存、租户公平性、队列积压 | P50/P95/P99、吞吐、错误/超时、资源、24h持续负载 |
| 故障/灾备 | worker kill、队列/DB/对象故障、模型429/超时、磁盘满、备份恢复 | RPO/RTO实测、对账、恢复前删除/撤权重放 |
| 发布/迁移 | 新机安装、存量回填、契约兼容、灰度和回滚 | 固定版本包、执行记录、失败回退路径 |

代码覆盖率可作为质量信号（建议新核心逻辑分支覆盖≥80%），但不替代安全场景、算法效果或真实全栈测试。当前全仓静态检查遗留问题、真实模型与 JSON 容量缺口须列在研发任务中，不能继承历史“通过”标签。
