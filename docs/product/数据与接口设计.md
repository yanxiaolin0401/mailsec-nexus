# 数据模型与接口设计基线

> v1.1 概念/逻辑设计 · 对应 EVI/IAM/ING/CAS/EXP。不是已执行 DDL 或已实现 API。smart-search [现有字段约定](../../mailsec-smart-search/docs/detail/嵌套JSON接入与字段映射.md)保持兼容。

## 1. 标识与数据权威

| 标识 | 含义 | 不得混用 |
| --- | --- | --- |
| `tenant_id` / `project_id` | 平台授权作用域 | 不从用户填的 `sourceSystemId`、邮件域名推断 |
| `event_id` | 一次业务投递/接收事件 | 同内容多次投递可有不同事件；收件人数组不拆事件 |
| `source_id` / `source_event_id` | 已绑定来源及其业务幂等键 | 仅在租户/来源范围内唯一；相同键不同载荷冲突 |
| `artifact_id` / `content_sha256` | 原文/附件/报告对象及内容摘要 | SHA 不当授权凭据；MD5 仅兼容上游关联，不作完整性根基 |
| 原报文 `Message-ID` | 不可信报文字段 | 可缺失/重复/伪造，不作主键 |
| `analysis_id` / `run_id` / `version_id` | 分析、实验或算法版本 | 新分析追加记录，不改历史意见 |
| `job_id` / `attempt_id` / `trace_id` | 业务任务、尝试与观测链 | 重试保留 job、增加 attempt；不同事件不按 trace 去重 |

PG 控制面记录状态与引用；对象存储保留原始证据；ClickHouse 保存可重建的检索投影。现有 `mail_records`/`mail_events` 及本地队列是独立版事实，不能描述成已具备下述租户 Schema。

## 2. PostgreSQL 逻辑实体

所有租户业务表带 `tenant_id`、创建/更新时间；项目级表带 `project_id`。下列字段为设计最小集，物理类型、索引和迁移在详细设计中补齐。

| 实体 | 关键字段/约束 | 关联与所有权 |
| --- | --- | --- |
| tenants / projects | id、status、region、retention_policy_id、quota_policy_id | 租户含多个项目，停用不等于删除 |
| users / identities / memberships | user_id、issuer/subject唯一、account_type(user/admin)、status；普通用户tenant/project归属 | 仅两类交互身份；管理员为全平台账号，无需每租户成员资格；类型只由管理员受控修改，禁止自助提权 |
| resource_shares / access_policies | owner_id、tenant/project、resource_ref、shared_user_ids、policy_version | 用户统一业务权限加归属/共享约束，不建自定义角色/角色层级；管理员经显式管理路径全平台读写 |
| sessions / auth_transactions | subject、account_type、login_mode、active_tenant、expires/revoked_at、认证事务绑定 | 用户会话须匹配租户；管理员会话全平台，操作另带目标范围；mode来自服务端事务并与身份校验 |
| service_accounts / credentials | tenant/project/source、scopes、expires_at、revoked_at | 存随机 token 验证摘要或凭据引用，不存可读回的 token |
| sources | tenant/project、external_source_key、schema_version、status | 外部来源标识须匹配凭据绑定；未知来源拒绝 |
| ingest_receipts / mail_events | event_id、source_id、source_event_id、payload_hash、artifact_ref、accepted_at、index_status | 有来源键时唯一 `(tenant_id, source_id, source_event_id)`；无键每次新事件 |
| evidence_objects | artifact_id、tenant/project、sha256、size、media_type、storage_key、encryption_key_ref、hold/status | 同租户去重可选，生命周期需引用计数；存储键不对普通用户公开 |
| analysis_runs / findings | event_id、producer/version、policy_version、status、verdict、evidence_refs、model/usage | 风险与运行状态分开；追加版本，禁止分析覆盖人工标签 |
| labels / label_revisions | target_ref、taxonomy_version、label、annotator、reason、review_state | 双人复核/仲裁；用于实验需固定版本 |
| cases / case_links / comments | case_id、assignee、severity、state、revision、linked_object | 一个案件关联多事件/告警；同域外键与乐观锁防覆盖 |
| alerts / campaign_members | source_alert_key、event_ref、features、cluster_version、confidence | S3；未匹配和不确定关联独立保存 |
| parser_versions / rule_versions | artifact_ref、parent、status、dataset/eval_ref、scope | 版本不可变，生效指针受审查；支持回滚 |
| approvals / deployments | subject_version、requester、reviewer、decision、effective_scope/time | 用户候选由管理员审核；管理员直接发起操作须通过安全门禁并二次确认，不强制第二管理员；记录申请/确认者、影子/生效状态 |
| datasets / sample_members / splits | source/license、hash_manifest、label_version、split_group、external_send_allowed | 数据集快照和切分不可隐式变化；研究集跨域使用需明确授权 |
| experiments / metrics | run_id、code/container/config、seed、dataset/split、metrics/report_ref | 独立记录失败/未知/超时/成本，不只存成功指标 |
| jobs / job_attempts / outbox | type、owner、scope、state、lease、retry_at、result_ref、dedup_key | outbox 与业务状态同事务；租约过期重领，避免永久 running |
| exports / deletion_requests | scope_snapshot、approvals、expires_at、delivery/deletion_state | 导出/删除有审计及保全约束，不能通过普通 CRUD 立即清库 |
| policies / model_configs / audit_events | scope、version、secret_ref、actor/action/object/result、trace_id | 凭据引用至秘密管理；审计追加、归档权限分离 |

**约束要求**：跨表外键包含租户（必要时项目），普通用户应用授权和RLS双层，管理员跨租户读写走受信管理策略；状态迁移用事务/乐观锁；禁止级联删除证据或审批历史。全局字典不携带租户敏感信息。正文/附件大对象不放 PG。

## 3. ClickHouse 与对象存储

### 3.1 检索投影

- 产品投影至少含租户/项目、事件/来源、采集/邮件时间、收发数组、主题/正文检索字段、附件元数据、数据质量、当前分析摘要和生产者版本。
- 查询授权字段不可由模型更新。当前结果视图需说明“截至何时/哪个版本”，历史分析用 append-only 记录。
- 主排序/分区根据租户基数、热时间窗、保留期、去重与典型查询实测；新版本表不强套现有哈希16分区或旧示例月分区。
- 精确总数只在查询预算内计算；超预算返回明确状态或用户选择异步统计，禁止把截断数量当完整总数。
- 索引 TTL/异步 mutation 不是实时撤权；删除/隔离先在授权可见性层生效，再后台物理删除并对账。
- 保留重建来源：原始引用、清洗/解析/规则版本和状态；“全量重建”需可重跑且避免占满在线资源。

### 3.2 对象存储

建议逻辑路径 `tenant/project/type/yyyy/mm/artifact_id`，不使用用户上传路径，文件名仅为元数据。桶不公开，服务端校验大小/格式/哈希；下载带 `Content-Disposition: attachment` 和安全头，不自动运行 HTML/附件。

区分原始 JSON、原始 EML、附件、解析器候选、实验报告和导出，配置不同权限/保留策略。只得到 JSON 元数据时不可制造“原始 EML 已保全”的记录。对象锁/版本功能以最终选型实际能力验收。

## 4. 生命周期与备份恢复

- 创建时附授权/来源、地域、保留策略及保全标记；研究公开语料集中在项目数据目录/受控对象存储，不进入 Git 或镜像。
- 到期删除：保全检查 → 用户不可见/任务禁止新读取 → 撤销导出与缓存 → 删除投影/衍生对象 → 引用计数归零后删原文 → 核验回执。存在其他合法引用不能直接删共享对象。
- 保全优先于自动过期；修改保全/留存需审核。归档不等于删除；软删除不等于物理删除。
- 备份中的删除以约定轮换期限落实，不能承诺“立即从所有备份消失”。删除台账独立保留，恢复后先重放删除/撤权，再开放查询；密钥删除也必须验证所有副本策略。
- PG PITR、对象快照/版本、ClickHouse 备份或重建清单、队列/回执对账分别设计；密钥恢复材料与数据备份独立受控保存。定期实际恢复，不只检查备份文件存在。

## 5. 平台 API 边界（拟议）

前端只调用平台契约，例如 `/api/platform/v1`；这是**拟议新命名空间**，不把现有模块 `/api/v2/mails`、`/api/v1/*`、`/v1/*` 原地改成新含义。来源接入保留兼容路由的适配网关，并把来源凭据映射成可信作用域。后续若统一公共路径，必须发布迁移/弃用版本。

| 能力 | 接口示例 | 语义/鉴权 |
| --- | --- | --- |
| 登录/会话 | `/auth/login`、`/auth/callback`、`GET /session`、`POST /session/logout` | 服务端绑定login_mode=user/admin并校验真实账号类型；管理员MFA；登录模式不直接产生权限 |
| 用户范围 | `POST /session/active-tenant` | 用户切租户校验成员关系；管理员在后台指定目标范围，不伪装用户会话 |
| 接入 | 兼容 `POST /api/v2/mails`、EML raw/upload；平台批导 `POST /imports` | 来源凭据、限额；持久接收返回202和回执，不承诺索引完成 |
| 任务 | `GET /jobs/{id}`、`POST /jobs/{id}/retry`、`POST /jobs/{id}/cancel` | 用户资源归属/共享；管理员可管理全部任务；attempt和副作用说明 |
| 查询 | `POST /mail/search`、`POST /mail/stats` | 敏感筛选不放 URL；限制计划/扫描量、稳定 cursor |
| 详情/证据 | `GET /mail/{id}`、`GET /artifacts/{id}/download` | 详情与原文权限分开；不可猜测路径读取对象 |
| NL | `POST /query-plans`、`POST /query-plans/{id}/execute` | 预览绑定用户、作用域、策略、有效期；执行重新鉴权 |
| 检测/SOP | `POST /mail/{id}/analyses`、`POST /sop-runs` | 长任务202，模型外发与配额双校验 |
| 案件 | `POST /cases`、`PATCH /cases/{id}`、`POST /cases/{id}/transitions` | 状态机/版本条件，避免任意状态字段 CRUD |
| 实验/发布 | `POST /experiments`、`POST /versions/{id}/approval-requests`、`POST /deployments` | 用户候选由管理员审核发布；管理员操作也必须满足评测/安全门禁和二次确认，拒绝未通过版本 |
| 导出/生命周期 | `POST /exports`、`POST /deletion-requests` | 范围冻结、审批、配额、审计、到期撤销 |
| 管理/审计 | `/admin/tenants`、`/admin/users`、`/admin/data/*`、`/admin/settings/*`、`/admin/audit` | 统一后台，仅admin身份；全平台数据读写，每项操作记录目标租户/资源；不设租户管理员路由 |

### 5.1 公共协议纪律

- OpenAPI 与 JSON Schema 进入版本控制；前端类型由契约生成并在 CI 校验，服务端仍执行运行时验证。
- 响应包含 `request_id`；错误统一 `code/message/details/retryable`，details 不含原文/密钥/栈。401 未认证、403 拒绝、404 不可见资源统一策略、409 幂等冲突/版本冲突、413 超限、422 不支持语义、429 配额、503 依赖不可用。
- 列表采用稳定排序 `(time, id)` 和签名游标；游标包含查询指纹/作用域/有效期。审计查询与敏感列表限制分页与导出。
- 写动作支持作用域内幂等键和载荷哈希；保留期/历史回执归档必须明确。删除后对合法重放是拒绝、恢复还是新事件须按来源合同冻结，不能自动复活已删除数据。
- UTC ISO8601 时间；金额/成本避免浮点累计误差；请求/响应大小、批量数、超时、重试建议、部分成功逐项定义。
- 来源未知业务字段按现有兼容规则忽略并记录质量；身份/权限/版本等控制字段严格校验，不能因“容错”接受未知特权参数。
- 租户激活、导出、发布、模型外发等写动作不能只做客户端确认；服务器验证会话、CSRF、权限、策略版本与审批。

## 6. 跨模块事件契约（目标）

共享 envelope：`schema_version, event_type, event_id, tenant_id, project_id, aggregate_id, producer, producer_version, occurred_at, trace_id, causation_id, payload_ref`。队列仅传最小引用和受限元信息，原则上不放完整正文/密钥。`event_id` 此处是**总线事件标识**，业务邮件 ID 明确为 payload 的 `mail_event_id`，避免名字歧义。

契约包括 `RawMessageRef`、`ParsedMessage`、`MailAnalysis`、`AlertEvent`、`RuleCandidate`、`RuleEvaluation`、任务进度/审核结果；共享库只定义 Schema/类型，不共享数据库写权限。新字段向后兼容、未知枚举处理、版本升级/弃用有契约测试；消费者遇到不支持版本进入明确失败/死信，不悄悄按旧语义执行。

## 7. 必测的数据不变量

1. 两租户相同来源键/邮件 SHA 不互相去重、查见或借缓存获知对方数据。
2. 平台用户同租户不同项目/未共享资源不能越权关联；管理员跨租户读写须走显式管理路径，保留资源归属与审计；最高操作权限不允许构造违反租户外键约束的非法关联。
3. JSON 同来源键同载荷重放返回同一事件；同键异载荷409；无键重放为新事件；EML 历史去重兼容。
4. 进程/网络在持久化、发布、处理、投影写入、ACK 的任一步故障后，业务事件不丢失/不多计，可对账。
5. 删除/撤权后，即使旧游标、任务重试、旧报告链接、备份恢复也不能恢复无授权可见性。
6. user账号即使选择管理员模式、改role/tenant参数或复用管理员游标也不能提权；admin登录可访问全部租户数据，切模式/禁用/降权后旧会话失效。
7. 未知风险、缺字节、部分解析、模型超时不能被聚合统计成正常样本；不可用计入评测分母规则。
