# 技术依据与关键决策记录

> 检索/整理：2026-10-22。以下官方文档用于限定能力边界；设计推导不代表实现已验证。滚动文档须针对最终锁定版本复验，不据此盲目升级运行环境。

## 1. 官方依据

| 主题 | 来源 | 本项目采用的约束 |
| --- | --- | --- |
| PostgreSQL RLS | [PostgreSQL 18 Row Security](https://www.postgresql.org/docs/18/ddl-rowsecurity.html) | superuser/BYPASSRLS与表owner存在绕过边界；应用与迁移身份分离、按需FORCE、池上下文与跨域测试；TRUNCATE不靠RLS保护 |
| PG版本支持 | [Versioning Policy](https://www.postgresql.org/support/versioning/) | PG14支持截止2026-11-12；原题14.18不直接作为新生产基线；受支持版本与安全小版本经兼容验证锁定 |
| ClickHouse权限 | [Row Policy](https://clickhouse.com/docs/reference/statements/create/row-policy) | 查询/写入/维护权限分离；可改表用户不受该机制充分保护；共享账号参数不等于强租户隔离 |
| ClickHouse文本索引 | [Text Indexes](https://clickhouse.com/docs/reference/engines/table-engines/mergetree-family/textindexes) | 分词器/谓词/版本/旧数据物化影响索引命中；中文子串/短语需实测，不能假定自动覆盖 |
| 文件接收 | [OWASP File Upload](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) | 不信上传类型/文件名，限制大小、展开、权限和存储，扫描不等于安全保证 |
| LLM注入 | [OWASP Prompt Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html) | 邮件是间接注入入口，独立工具权限/参数/人工门禁，不能只靠提示词防护 |
| 登录协议 | [OIDC Core 1.0 errata 2](https://openid.net/specs/openid-connect-core-1_0.html)、[RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html) | 授权码+PKCE S256、令牌/回调校验；认证不替代业务授权，不用implicit/password简化 |
| 私有对象 | [S3 Bucket Policy Examples](https://docs.aws.amazon.com/AmazonS3/latest/userguide/example-bucket-policies.html) | 前缀不是ACL，Get/Put/Delete/List分别限制；S3兼容产品需验证策略/条件键差异 |
| 观测隐私 | [OpenTelemetry Sensitive Data](https://opentelemetry.io/docs/security/handling-sensitive-data/) | 采集最小化/脱敏需自己配置；哈希低熵邮箱不等于匿名，trace不存正文/key |
| 消息可靠性 | [RabbitMQ Confirms](https://www.rabbitmq.com/docs/confirms)、[Reliability](https://www.rabbitmq.com/docs/reliability) | 发布确认与消费ACK独立；至少一次仍可能重复，幂等/持久化/对账为业务责任 |
| 企业UI组件 | [Ant Design of React](https://ant.design/docs/react/introduce/) | React/TypeScript组件库作为拟议交互基础；组件可用不替代权限、无障碍和响应式验收 |
| 前端构建 | [Vite Guide](https://vite.dev/guide/)、[TypeScript](https://vite.dev/guide/features#typescript)、[Static Deployment](https://vite.dev/guide/static-deploy) | 支持React/TS模板；build不执行类型检查；preview不是生产服务器 |
| API部署 | [FastAPI Deployment Concepts](https://fastapi.tiangolo.com/deployment/concepts/) | TLS、启动/重启、内存、副本和迁移分别考虑；多worker不自动共享内存或形成HA |
| 可访问性 | [WCAG 2.2](https://www.w3.org/TR/WCAG22/) | AA为产品设计/验收目标，键盘/焦点/对比度/响应式需人工与自动组合验证 |

技术栈 React/TypeScript/FastAPI 延续原平台方向；新增PG/对象/持久队列是事务、证据和恢复需求驱动，不是官方文档要求所有企业产品必须采用此组合。Rspamd/ClamAV沿用已验证链路，检测效果仍受现有基线限制。

## 2. 决策记录

| ADR | 决策/状态 | 理由、代价与重新评估条件 |
| --- | --- | --- |
| ADR-001 | **已定需求**：smart-search → header-parser → threat-trace，平台底座随阶段交付 | 最新用户要求；撤销旧parser先行依赖，不拆毁已可运行search |
| ADR-002 | **产品基线**：前后端分离、模块化后端/独立Worker，非默认全微服务 | 降低小团队部署/事务复杂度；独立扩容/团队边界出现后再拆服务 |
| ADR-003 | **已定/扩展**：ClickHouse继续邮件检索，PG新增业务事务，对象保存证据 | 满足查询和审批各自语义；增加运维成本但避免OLAP承担事务；ES非首版依赖 |
| ADR-004 | **用户裁定更新**：仅平台用户user与后台管理员admin；登录页区分用户租户/管理员模式 | 用户按租户/资源隔离；管理员拥有最高操作及全平台数据读写权，无需租户额外授权。撤销多层管理角色；显式管理路径、MFA、二次确认和审计保留 |
| ADR-005 | **拟议实现**：RabbitMQ+outbox+幂等消费 | 持久接收与故障恢复，避免跨库/队列伪事务；若企业现有Kafka且团队可运维再比较 |
| ADR-006 | **拟议实现**：OIDC+BFF会话，成熟IdP管理凭据/MFA | 不自建密码学/账号安全体系；独立部署仍需IdP。供应商/版本由企业环境确定 |
| ADR-007 | **已定边界**：静态扫描、代码沙箱、动态沙箱分开 | 安全能力如实描述；动态执行P2，代码生成一旦执行必须先有强隔离 |
| ADR-008 | **已定边界**：外发默认关闭、脱敏授权、模型只读工具 | 数据/提示注入/费用控制；外部模型失效不拖垮基础查询 |
| ADR-009 | **已定边界**：事件身份不等于内容哈希，来源字段不等于租户身份 | 保留JSON事件语义、EML兼容，防来源伪造越权；需要迁移映射和对账 |
| ADR-010 | **待冻结**：生产组件具体版本、部署档位、SLO/资源与商业许可 | 未有完整生产样本/预算/环境，不假定安装完成或签SLA；版本在实施前形成锁文件/镜像摘要 |

## 3. 与模块详细需求的兼容说明

- 不改smart-search当前JSON 34列/现有接口的承诺；新增产品作用域/映射走版本化迁移。
- 当前轻量Web无框架要求是独立阶段约束；正式平台React前端是新增系统级要求，二者不是同一交付物。
- 模块“ClickHouse单引擎”指邮件检索，不禁止平台事务库；基础解析仍由search自主提供，S2增强通过适配接入。
- HTTP8080是本地/内部服务入口；生产TLS反代不等于另建SMTP网关。
- 原始题目材料、企业图片、历史报告不重写为新要求；与本次产品化目标的差异通过顶层基线和ADR说明。
