# 工作区 Codex 对话与执行规范

- 自主执行明确、低风险、可回滚的实现与验证，不反复请求继续许可；破坏性操作、权限扩大或真实外部模型调用需明确授权。
- 本模块为【mailsec-nexus】三大功能之一，功能实现与修改直接同步网页平台工作区-platform，而不是完全独立开发
- 研发需求以 `docs/detail/基于大模型的邮件数据分析与智能检索系统_研发任务与推进计划.md` 为主线；输入契约以更新的 `docs/统一输入流交付包/邮件离线分析_统一输入流标准契约规范.md` 为准。冲突须明确记录，不静默丢字段或伪造支持。
- 优先邮件存储管理、可靠接入与检索。保留现有数据，不自动删除、清库或重新导入全库。
- 项目日志目录为工作区根目录的 `/logs`（即本仓库 `logs/`，不是宿主机 `/logs`）。每次会话开始、实质性操作/决策、修改、验证、失败/恢复及交付后及时追加日志。记录时间、动作、结果、验证证据、下一步。
- 没有重要交付，不在 `docs/` 下新建文档。普通进展、差异清单和检查结果写入 `logs/`，并在对话中直接回复。输入交付包视为需求原件，不随意修改。
- 实时更进项目进度，用人类语言精炼地总结修改、更新、决策、问题等信息，写入`docs/progress.md`。每次写入内容格式不用每次相同，不覆盖上次写入，直接阐述事实不进行防御性篡写。
- 允许使用 Codex 原生子代理处理独立、边界清晰的任务；主代理负责集成与最终验证。并行编辑须明确文件所有权，不能撤销他人改动。
- 修改前阅读代码和适用规范；修复须补回归测试。完成前运行针对性和全量测试及适用静态检查，明确尚未验证/未通过项。
- 复用现有模式，不擅自新增应用依赖；重构先锁定现有行为。云端结构变更仅允许与当前任务相关的非破坏性扩展，保留回退路径。
