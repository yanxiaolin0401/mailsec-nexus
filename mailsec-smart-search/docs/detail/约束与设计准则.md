# 约束与设计准则

## 已明确的技术与安全约束

| 领域 | 约束 |
| --- | --- |
| 数据与标识 | 保留原始 EML 字节/哈希及来源引用；解析字段是可重算的衍生数据。邮件头须保留有序多值表示。系统稳定 `message_id` 与报文 `Message-ID`、内容哈希分开，不能仅以 `Message-ID/MD5` 当唯一键。当前独立运行，内部记录也须带解析/分析版本和证据引用。 |
| 接入与解析 | **HTTP 8080 为唯一当前入口**；主接收嵌套 JSON，原始 EML 请求体或文件上传为兼容路径。以 RFC 5322/MIME 为解析基线。限制报文大小、附件/嵌套深度、解码量、处理时间；畸形样本须隔离记录，不使服务崩溃。当前不启用 SMTP。 |
| 存储 | 首版采用 **ClickHouse 单引擎**，选当时最新的**兼容且通过项目测试**的稳定版本并锁定，不盲目使用浮动 `latest`。旧 EML 表与新事件表分别建模；月度时间分区是早期参考方案，不是两表共同的既定实现。新事件表的物理分区/排序与原规范示例不同，须以实际 DDL 和压测复核；批量写入是共同要求。Elasticsearch 不是首版必装依赖。 |
| 查询与工具调用 | 支持多条件过滤、分页、详情及统计；限制允许字段、查询复杂度、执行时间、并发和结果/导出量。模型仅能给出白名单 JSON 过滤/工具计划；后端校验权限与参数，并以固定参数化模板编译 SQL。模型文本不能作为 SQL/DSL 或任意操作直通数据库。 |
| 模型 | 适配 OpenAI/Anthropic 两种协议格式，并通过获授权的第三方 API Key 完成真实接口联通测试。配置 BaseURL、密钥和认证头；请求有超时、有限重试、退避与降级。邮件文本是不可信输入；未授权时不得向第三方发送真实企业邮件。凭据不得写入代码或 Git。 |
| 研判 | 模型独立判断与开源检测算法结果**分别记录再融合**，保留各自分数/证据、冲突与失败状态；不把二者一致当作真值。风险等级、依据与具体证据特征以结构化结果返回，人工结论另行留痕。批量 SOP 的部分结果和失败项须显式呈现。 |
| 工程 | Git 分支和可读提交、阶段 Tag、锁定依赖、独立 fixtures、解析规则单测、每次改动回归、一键评测和错例台账；大样本不得入库。AI 生成代码经人工审查和本地测试再合入。 |

除 ClickHouse 外，企业补充说明未强制其他技术栈；当前实现采用 Python 3.12 与 FastAPI；轻量 Web 控制台不新增前端框架或构建依赖。具体依赖按兼容性测试锁定。

## 公开数据与开源检测候选

- [CMU Enron](https://www.cs.cmu.edu/~enron/) 约 50 万封，可供导入/检索压测；其附件已移除且无恶意邮件金标准标签，**不能单独用于检测准确率验收**。可用 [SpamAssassin 公共语料](https://spamassassin.apache.org/old/publiccorpus/readme.html) 做垃圾邮件基线、[Nazario 钓鱼语料](https://monkey.org/~jose/phishing/README.txt) 补充钓鱼样本；逐项核验许可、脱敏和标注，原始样本不提交 Git。
- 非 AI 检测暂以 [Rspamd](https://docs.rspamd.com/about/features/) 为优先验证候选：可接收 EML 并返回分数及命中规则，便于同模型独立判断对照；[SpamAssassin](https://spamassassin.apache.org/downloads) 作可选对照。若验收包含恶意附件，再评估 [ClamAV 扫描集成](https://docs.rspamd.com/modules/antivirus/)。最终选型以统一留出集的误报/召回、延迟与部署代价为准，不宣称未经实测的“最有效”。

## 参考方案，不直接作为硬性验收阈值

- 推荐轻量直写：接收/本地 SQLite WAL FULL 持久队列 → 批量写 ClickHouse。满 **2000 条或 2 秒**批写是截图中的示例参数；Kafka/Redis Stream 削峰为进阶可选，不是首版必需。
- 参考表 `mail_records` 含发送时间、收发地址/域名、主题、正文、附件名称/哈希、SPF 结果、原始头等；`PARTITION BY toYYYYMM(send_time)`、`ORDER BY (send_time, from_domain, mail_id)` 是旧方案的历史参考，不照抄为已验证最优结构。示例表中的 `raw_headers String` 不能代替原始字节和有序多值头。
- 模型单次超时 **15 秒**、网络抖动/429/5xx 指数退避最多 **2 次**是配置示例；须按模型配额、总请求时限及实际测试冻结。只重试可恢复的失败，避免无限重试。
- Docker Compose 新机部署已有实现；**轻量 Web 是必做**，CLI 为辅助。`Magpie` 是页面/多模型方案的参考工具，不是必装依赖或既定产品集成。

## 与旧方案的裁定

1. 先前“ClickHouse/Elasticsearch 待选”由企业细则更新为 **ClickHouse 单引擎**，且**不要求 Elasticsearch Query DSL**；本期 NL2Query 仅走受限 ClickHouse 查询路径。ClickHouse 无现成实例，由本模块自部署并锁定兼容版本。
2. 本轮明确 **HTTP 8080 JSON 推送为主、EML 为兼容**，覆盖早期“HTTP/SMTP 二选一”的旧裁定；不推导出生产邮件网关、实时拦截或开放公网服务。
3. 截图提出“后端直接执行生成语句”的业务目标须服从项目[AI 安全约束](../../../docs/项目目标与顶层约束.md)：先校验/约束，再执行安全查询。
4. 当前模块独立开发，不与其他课题交叉；原文中的跨模块数据契约仅作为未来集成方向，不是本期前置依赖。
