# 邮件离线安全分析系统 — 数据输入输出与接口规范说明书

> **文档地位**：字段/API 基线。原平铺投递样例保留为兼容示例；本轮已将主输入、`202` 语义及参考 DDL 的未研判风险默认值更新。当前 `mail` 嵌套封装、`text_content` 第 34 列与实际物理 DDL 差异见[嵌套 JSON 映射](嵌套JSON接入与字段映射.md)。

本规范定义了**邮件离线分析系统**在数据接入、智能分析、数据存储与查询检索全流程的数据模型与字段契约，专门针对现代开发与 AI 辅助编程（AI Agent）进行了清晰化定义，用于指导系统开发与功能验收。

---

## 1. 系统总体架构与技术栈建议

系统整体划分为四大逻辑层级：**数据接入层 ➔ 异步缓冲管道 ➔ 存储主仓 ➔ 查询展示层**。

```
[前置系统 / 邮件采集源]
          │
          ▼ 1. 数据接入 (HTTP POST 直接投递明文 JSON)
   【数据接入层 Ingestion】 (接收报文、字段清洗校验、生成唯一 eventId)
          │
          ▼ 2. 消息解耦缓冲
   【异步消息管道 Pipeline】 (推荐选型：Kafka 消息总线)
          │
          ▼ 3. 安全分析与持久化
   【数据持久层 Storage】   (推荐选型：ClickHouse 分析型列存)
          │
          ▼ 4. 多维检索与线索反查
   【查询服务层 Query API】 (RESTful 检索、态势统计、详情钻取)
          │
          ▼
   [管理控制台 / 安全运营人员]
```

### 推荐技术栈
- **语言**：Python 3.12+ (FastAPI) 或 Java 21 (Spring Boot 3.x)
- **消息总线**：Kafka (topic 如 `mailwatcher.offline.input.v1`、`mailwatcher.offline.analyzed.v1`)
- **分析型数据库**：ClickHouse（宽表列式存储，负责秒级 OLAP 聚合统计与多维排查）

## 2. 核心设计原则与字段兜底纪律

### 2.1 唯一标识与发件模型约定
1. **事件 ID（`eventId`）不约束生成方式**：
   - 保证系统全局唯一即可，**允许自由采用 UUID（如 `uuid4().hex`）、雪花算法（Snowflake）或自增序列**。
   - **同一邮件不同时间发出的处理**：同一封邮件在不同时间投递，属于不同的独立安全事件，赋予不同的 `eventId` 分别记录。
2. **“一对多”群发邮件的数据模型**：
   - 一封邮件同时发给多个收件人（含抄送）时，在数据库中**只存 1 条记录**，切勿按收件人数拆分多条重复记录造成数据冗余膨胀。
   - 发件人字段 `sender_account` 为单值字符串（发件邮箱）。
   - 收件人字段 `receiver_accounts` 为**收件人字符串数组**（如 `["userA@company.com", "userB@company.com"]`）。

### 2.2 字段基线与兜底占位规则
1. **基线字段必须完整**：学生可以在此基础上扩展自定义字段，但本规范列出的**所有核心基线字段在存储与输出时必须完整存在**。
2. **缺省兜底占位**：若某封邮件因格式特殊、上游未传或未能成功解析出某一字段，**严禁丢失字段或留为异常 `null`**，必须按照规范兜底占位：
   - **文本类字段**：无法获取时统一填充字符串 `"-"`（IP 类无法获取时填充 `"unknown"`）；
   - **数值/评分字段**：无法获取或未计算时统一填充 `0`；
   - **集合/数组类字段**：无内容时统一填充空数组 `[]`。
3. **输入容错原则（Postel's Law）**：上游报文中如果包含了未定义的额外扩展字段，系统必须静默忽略（不得因未知字段直接报错导致拒信丢信）。

## 3. 系统数据输入规范（Data Ingestion）

系统接入层对外暴露数据接收接口：`POST /api/v2/mails`。  
本地开发可在回环地址以 HTTP POST JSON 调试；跨主机或生产部署必须由可信反向代理提供 TLS、鉴权与访问控制。无需自定义 AES 报文加解密。

### 3.1 接收报文字段模型（主格式嵌套，平铺兼容）

主格式为 `{sourceSystemId, sourceEventId, eventTime, mail:{...业务字段}}`；下表前三项在顶层，其余在 `mail` 对象。历史平铺 JSON 和 `data` 对象可兼容，但不能递归猜测未知层级。标为“是”的字段是上游应提供的契约字段；接入容错时缺失字段按占位规则处理并标记数据质量，缺来源键的每次投递都是独立事件。

> 💡 **给 AI Agent 的实现提示**：上游输入字段名由于历史原因包含混合命名（如全小写的 `senderaccount` 和带下划线的 `attachInfos_md5`）。编写 Model 时，**建议支持别名映射（Alias）或做大小写兼容处理**，避免直接修改字段名导致反序列化失败。

| 字段名 (Field) | 类型 | 必填 | 缺省占位值 | 业务含义与说明 |
|:---|:---|:---:|:---:|:---|
| `sourceSystemId` | String | 是 | `"-"` | 数据来源系统编号 / 租户标识（如 `tenant-01`） |
| `sourceEventId` | String | 是 | `"-"` | 上游原系统的原始事件唯一编号（用于全链路对账与幂等排重） |
| `eventTime` | String | 是 | 当前时间 | 邮件采集/产生时间戳（ISO-8601 标准格式，如 `2026-10-14T09:00:00+08:00`） |
| `from` | String | 是 | `"-"` | 发件人原始展示字符串（如 `张三 <zhangsan@catl.com>`） |
| `senderaccount` | String | 是 | `"-"` | 发件人纯邮箱地址（清洗去除尖括号与多余空格） |
| `senderhost` | String | 否 | `"-"` | 发信客户端的主机名或 HELO / EHLO 域名 |
| `accountnick` | String | 否 | `"-"` | 发件人昵称展示名 |
| `replyTo` | String | 否 | `"-"` | 邮件标头中的 Reply-To 回复地址 |
| `toaccount` | String | 是 | `"-"` | 主收件人邮箱地址 |
| `tonick` | String | 否 | `"-"` | 收件人昵称 |
| `allReceiverAccount`| String | 否 | `"-"` | 全部收件人完整列表（多个地址建议逗号分隔） |
| `subject` | String | 是 | `"-"` | 邮件主题文本 |
| `ip` | String | 是 | `"unknown"`| 上游声称的发信公网出口 IP（落库至 `sender_ip`，未做来源真实性验证） |
| `clientip` | String | 否 | `"unknown"`| 内部终端客户端 IP（如通过内网 Webmail 登录的客户端 IP） |
| `textContent` | String | 否 | `"-"` | 清洗 HTML 标签后提取的邮件纯文本正文（去除 CSS/JS 代码） |
| `mailHeaderList` | String | 否 | `"-"` | 邮件原始完整 Header 标头文本（用于协议与中继溯源） |
| `urls` | String/Array| 否 | `"-"` | 提取的外链原始信息（字符串或数组形式均可，入库清洗为数组） |
| `attachInfos_md5`| String| 否 | `"-"` | 附件 MD5 列表（多个附件用分号或逗号分隔） |
| `attachInfos_filename`| String| 否| `"-"` | 附件文件名列表（多个附件用分号或逗号分隔） |

### 3.3 接入响应（HTTP 202 Accepted）

`202` 表示本地 SQLite WAL FULL 队列已提交，不表示 ClickHouse 已可查询。响应另带 `jobId` 供 `/api/v2/jobs/{job_id}` 查看异步状态；时间按服务端实际时区返回。相同来源键与相同载荷重试返回同一回执，同键不同载荷为 `409`。
```json
{
  "eventId": "evt-77a83d1c-29b0-4f51-b841-3d9a19c80001",
  "sourceSystemId": "tenant-01",
  "sourceEventId": "origin-9988221",
  "traceId": "trc_4b58e7456d9a4f669a8820f4c01e9123",
  "status": "accepted",
  "jobId": "example-job-id",
  "acceptedAt": "2026-10-14T09:00:01+08:00"
}
```

## 4. 存储层字段规范（ClickHouse 表结构）

本表给出 **33 个基线分析列**；本项目另增 `text_content` 第 34 列以支持正文检索。以下 DDL 是规范参考，不是当前运行实例的物理分区、排序或时区配置。

### 4.1 规范参考 DDL（运行实例以源码为准）
```sql
CREATE DATABASE IF NOT EXISTS mail_offline;

CREATE TABLE IF NOT EXISTS mail_offline.mail_events
(
    event_id                String                              COMMENT '事件全局唯一标识 UUID',
    event_time              DateTime64(3, 'Asia/Shanghai')      COMMENT '邮件事件产生时间（毫秒级，分区键依据）',
    ingested_at             DateTime64(3, 'Asia/Shanghai')      DEFAULT now64(3) COMMENT '入库时间（ReplacingMergeTree 版本去重列）',
    source_type             LowCardinality(String)              DEFAULT 'MAIL_OFFLINE_HTTP' COMMENT '数据源接入类型',
    source_system_id        LowCardinality(String)              DEFAULT '-' COMMENT '来源系统编号/租户标识',
    source_event_id         String                              DEFAULT '-' COMMENT '上游源系统事件原始 ID',
    trace_id                String                              DEFAULT '-' COMMENT '全链路追踪 Trace ID',
    payload_hash            String                              DEFAULT '-' COMMENT '原始数据载荷哈希值',
    mail_hash               String                              DEFAULT '-' COMMENT '邮件内容唯一指纹 MD5',
    sender_account          String                              DEFAULT '-' COMMENT '发件人邮箱账号',
    receiver_accounts       Array(String)                       DEFAULT [] COMMENT '收件人账号列表（数组形式，支持单封多投）',
    subject                 String                              DEFAULT '-' COMMENT '邮件主题',
    sender_ip               String                              DEFAULT 'unknown' COMMENT '发件人公网真实出口 IP',
    ingress_ip              String                              DEFAULT 'unknown' COMMENT '网关接收/代理接入点 IP',
    sender_country          LowCardinality(String)              DEFAULT '-' COMMENT '发件人所属国家代码（GeoIP）',
    sender_isp              LowCardinality(String)              DEFAULT '-' COMMENT '发件人网络运营商（GeoIP）',
    risk_verdict            LowCardinality(String)              DEFAULT 'unknown' COMMENT '未研判 unknown；有证据后可为 pass, alert, reject',
    risk_level              LowCardinality(String)              DEFAULT 'unknown' COMMENT '未研判 unknown；有证据后可为 low, medium, high',
    risk_score              UInt8                               DEFAULT 0 COMMENT '综合风险量化分值（0~100 整数）',
    feature_tags            Array(String)                       DEFAULT [] COMMENT '安全策略命中的特征标签数组',
    data_quality_tags       Array(String)                       DEFAULT [] COMMENT '数据质量异常与解析状态标签数组',
    sender_host             String                              DEFAULT '-' COMMENT '客户端 HELO 主机名或发信代理域名',
    suspicious_string       String                              DEFAULT '-' COMMENT '命中敏感/可疑特征关键词明细',
    malicious_sender_ip     String                              DEFAULT '-' COMMENT '威胁情报匹配到的恶意 IP 标记',
    tenant_email_addr_url   String                              DEFAULT '-' COMMENT '命中的租户仿冒/可疑 URL 明细',
    external_urls           Array(String)                       DEFAULT [] COMMENT '正文中提取的全部外链 URL 列表',
    external_attachments    Array(Map(String, String))          DEFAULT [] COMMENT '附件元数据列表（含 filename, md5, size 等）',
    mail_headers            String                              DEFAULT '-' COMMENT '邮件原始完整 Header 文本',
    mail_date               DateTime64(3, 'Asia/Shanghai')      DEFAULT now64(3) COMMENT '邮件头原生声明的 Date 时间戳',
    reply_to                String                              DEFAULT '-' COMMENT '邮件回复地址 Reply-To',
    src_email_address       String                              DEFAULT '-' COMMENT '原始发件人邮箱（与 sender_account 对齐）',
    to_email_address        String                              DEFAULT '-' COMMENT '首个/主收件人邮箱字符串',
    raw_json                String                              DEFAULT '-' COMMENT '受控审计用原始 JSON，不通过普通查询返回',
    text_content            String                              DEFAULT '-' COMMENT '纯文本正文，供主题/正文检索'
)
ENGINE = ReplacingMergeTree(ingested_at)
PARTITION BY toYYYYMM(event_time)
ORDER BY (toDate(event_time), event_time, event_id);
```

> 💡 **给 AI Agent 的实现提示（避免 ClickHouse 去重计数陷阱）**：  
> `ReplacingMergeTree` 的去重是后台异步进行的。在编写查询或统计 API 时：
> - 统计总数：请使用 `SELECT uniq(event_id) FROM mail_events`，或者在查询详情时使用 `ORDER BY ingested_at DESC LIMIT 1`。

## 5. 系统输出与查询接口规范（Query API）

面向前端控制台或外部消费系统提供数据检索与展示。

> 下方旧版 JSON 响应是**业务字段示意**，不是本轮接口逐字节响应样例。本轮 `/api/v1/mails` 列表/详情实际返回 `snake_case` 字段，列表中的主题最多 512 字符、收件人前 20 个另带 `receiver_count`；`raw_json` 不对外返回。准确响应以运行实例的 OpenAPI 与[部署说明](../部署与使用.md)为准。

### 5.1 邮件多维检索列表接口（`GET /api/v1/mails`）

#### 1. 查询请求参数（Query Params）
- `q`: 全文模糊匹配关键词（检索 `subject` 与 `textContent`）
- `account`: 匹配发件人或收件人邮箱
- `riskLevel`: 风险级别过滤（`unknown` / `low` / `medium` / `high`）
- `riskVerdict`: 判定结论过滤（`unknown` / `pass` / `alert` / `reject`）
- `senderIp`: 发件 IP 过滤
- `attachmentMd5`: 附件 MD5 精确过滤
- `attachment_name_contains`: 附件名称包含关键词（例如“发票”）
- `url`: 外链匹配过滤
- `startTime` / `endTime`: 时间区间过滤（ISO-8601，带时区）
- `limit` (默认 50，1~200) / `offset` (默认 0): 分页参数
- `cursor`: 历史规划项；本轮接口只实现受限 `limit`/`offset`，不接受游标参数

#### 2. 历史业务响应示意（非当前逐字节格式）

### 5.3 事件统计接口（`GET /api/v1/stats`）

复用 5.1 节已实现的过滤条件和鉴权，只返回匹配事件总量；不接受客户端 SQL 或 `cursor`。例如对本轮三封合成事件运行受限组合过滤，响应为：

```json
{"total": 3}
```

该 `3` 仅是[合成闭环报告](../reports/json-events-smoke.json)的数据，不是数据库的全局固定计数。
