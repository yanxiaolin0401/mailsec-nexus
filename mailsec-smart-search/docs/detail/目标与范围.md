# 目标与范围

## 总目标

独立建设邮件接收、解析、ClickHouse 检索与 AI 辅助分析系统：面向企业**约 10 万封/日**的邮件量，稳定处理大批量邮件，按条件快速定位可疑邮件，将模型研判及常见排查流程输出为**有证据、可复核**的结果，并提供轻量 Web 控制台、辅助 CLI 及可复现的工程交付。当前阶段**不依赖或对接其他两个课题**；日吞吐是容量规划输入，具体峰值与验收窗口待确认。

## 功能目标

| 编号 | 目标 | 预期能力 |
| --- | --- | --- |
| G1 | 邮件接收与结构化 | 首版以 **HTTP 8080 的嵌套 JSON 推送**为主，兼容原始 EML 请求体或文件上传；不实现 SMTP。清洗 JSON 中的标头、元数据、正文与附件信息，并对 EML 独立解析 RFC 5322/MIME；记录来源、异常状态和原始证据；入口不承担转发或拦截。 |
| G2 | 高吞吐存储检索 | 以 ClickHouse 为首版单引擎，批量写入；支持多条件组合过滤、分页、邮件详情及统计，保留既有 10 万封公开 EML 导入压测，并另测新 JSON 事件负载。 |
| G3 | 模型接入韧性 | 适配 OpenAI `/v1/chat/completions` 与 Anthropic `/v1/messages` 协议格式，在获授权且配置有效第三方 API Key 后提供真实模型调用；无密钥时明确降级；模型超时或不可用时重试/降级，不影响基础检索。 |
| G4 | 可解释智能分析 | 模型独立判定与开源检测算法结果融合，对指定邮件输出结构化风险等级（正常/可疑/恶意）、判定依据、证据特征和可能攻击手法；支持自然语言到受限查询条件的转换。算法以公开基准和本项目样本实测选型，不预称某算法普适最优。 |
| G5 | 标准化排查 | 预置可组合的查询过滤规则及分析提示模板，实现“条件初筛 → 嫌疑列表 → 模型批量研判 → 结构化报告”的一键排查 SOP。样例包括财务发票钓鱼、发信域仿冒、双后缀附件。 |
| G6 | 自然语言操作 | 用户以自然语言提出任务后，模型可在受控工具白名单内选择并调用功能（如邮件索引/检索），返回执行结果；工具权限、参数和副作用须由后端验证，不因模型建议直接执行任意操作。 |
| G7 | 工程交付 | 独立 fixtures、单元/回归测试、批量压测、一键评测、错例台账、接口与部署说明，以及可演示的全链路版本。 |

## 模块边界

- 本阶段由 `mailsec-smart-search` 自行完成接收、基础邮件头/MIME 解析、索引、检索、模型与检测算法融合，不引入 `mailsec-header-parser` 或 `mailsec-threat-trace` 的运行时依赖。
- 提供可独立运行的 API、轻量 Web 控制台及辅助 CLI；未来与平台集成可作为后续阶段，不是当前验收前置条件。
- 对“真实发件 IP”“路由真实性”只在可信接收点、信封及可用证据足够时下结论；否则输出候选线索或未知。AI 风险判断不替代人工复核或自动发布检测规则。
