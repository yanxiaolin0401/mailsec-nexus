# 阶段任务与验收

## 企业方五阶段任务

| 阶段 | 主要任务 | 里程碑交付物 |
| --- | --- | --- |
| 1. 架构与环境 | Git 分支规范；学习 RFC 5322/路由；确定 ClickHouse 表和 API 契约；建样本池。 | 仓库初始化与依赖清单、技术方案设计书（Schema/API）、fixtures 目录规范。 |
| 2. 解析与存储 | 以 HTTP 8080 接收嵌套 JSON、清洗标头与元数据；兼容 EML 解析；提取元数据、正文、附件哈希和发信路径线索；自部署 ClickHouse、批写并以 10 万公开样本压测；补充单测。 | 解析/接收模块 `v0.1`、解析核心测试、导入吞吐报告。 |
| 3. 检索与模型 | 多条件检索、分页；双协议模型适配与第三方密钥联通；开源检测算法基线及模型独立判断融合；超时/重试/降级；研判提示词和 NL2Query。 | 检索 API/文档、模型适配模块 `v0.2`、检测基线评测、Prompt 规范与错例台账 v1。 |
| 4. 集成与鲁棒性 | 必做轻量 Web 串联自然语言查询、邮件列表与详情；CLI 辅助新事件查询、旧 EML 排查与模型研判；处理非标、长文本及畸形样本；评估吞吐/时延。 | 全链路交互版本、改进的错例台账、稳定性测试记录。 |
| 5. 验收与答辩 | 企业导师样本验证；整理方案、验收报告与演示材料；可选 Compose 容器化。 | 项目部署/验收文档、答辩 PPT 和演示材料。 |

截图建议每周打里程碑 Tag（如 `v0.1-w1`）；**版本名是示例，具体周期以排期为准**。

## 验收证据清单

| 维度 | 企业方要求 | 应保存的证据 / 尚待冻结的口径 |
| --- | --- | --- |
| 导入容量 | 10 万封公开 EML 样本全量入库；新 JSON 事件需单独验证，无卡死、无 OOM。 | 样本清单/哈希、机器配置、版本、总耗时、吞吐、成功/失败数、内存峰值及可重跑脚本。 |
| 日吞吐 | 企业邮件量约 10 万封/日。 | 按企业峰值分布和持续运行窗口做容量压测；与上行“一次性导入 10 万封”分别报告，具体验收门槛待确认。 |
| 鲁棒性 | 企业导师经选定入口投递含超长头、混淆或畸形格式的样本，服务稳定解析、无崩溃。 | 投递入口、样本编号、异常分类、进程存活及错误记录；“稳定解析”不等于全部样本强制成功判定。 |
| 查询 | ClickHouse 多条件组合查询达到“秒级响应”。 | 代表性查询、数据量、并发、冷热缓存、响应时间分位数；“秒级”的具体阈值需企业确认。 |
| AI 研判 | 除风险标签外，给出逻辑和证据特征。 | 结构化输出、证据引用、未知/错误样本、人工复核记录。 |
| 检测融合 | 模型独立判定与开源算法结果融合。 | 同一留出集分别报告算法、模型及融合策略的效果、误报/漏报和延迟；不能仅凭公开样本宣称企业数据最优。 |
| NL2Query | 过滤条件准确、无语法错误。 | 自然语言—期望过滤条件对照集、非法/越权请求拒绝案例、实际执行结果。 |
| 自然语言操作 | 可按授权自动调用邮件索引/检索等功能。 | 工具白名单、权限/参数校验、调用审计及失败回退测试；写入类动作须明确用户确认策略。 |
| 故障恢复 | 网络抖动/模型超时可重试与降级，服务不宕机。 | 模拟 429、5xx、超时、不可用的测试；证明基础检索仍可用且失败明确返回。 |
| 工程质量 | 可复现、可回归，解析成功率/崩溃率/平均吞吐可报告。 | 锁文件、fixtures、单测/回归与一键评测输出；错例台账含编号、根因、措施。 |

**加分而非硬性门槛**：Compose 新机部署、CLI 辅助、易扩展性和错例复盘。轻量 Web 已由研发主线明确为必做。图片未给出准确率、吞吐条/秒、查询延迟分位数等数值硬阈值，不预填承诺。
