# mailsec-smart-search 需求分析

> 当前需求优先级及原始材料见[需求依据](detail/README.md)。本页是实施摘要；功能状态以[验证记录](验证记录.md)为准，不能把计划当作已验收。

## 1. 定位与边界

本模块独立完成 **HTTP JSON 接收 → 清洗与可靠排队 → ClickHouse `mail_events` 持久化 → 多维检索 → 双协议模型辅助的自然语言查询 → 轻量 Web 展示**。上游推送的邮件头、发信 IP 和认证结果属于声明数据，不自动等于可信证据。旧 EML 接收与 `mail_records` 继续兼容；不要求另两个课题提供运行时服务，不实现 SMTP、Elasticsearch 或在线拦截网关。

- **输入主格式**：`POST /api/v2/mails`，顶层 `sourceSystemId`、`sourceEventId`、`eventTime`，业务字段置于 `mail`；平铺和 `data` 对象仅为兼容。完整规则见[字段映射](detail/嵌套JSON接入与字段映射.md)。
- **接收语义**：`202` 表示 SQLite WAL FULL 本地队列已持久接收，不保证已写入 ClickHouse；worker 异步消费。来源键相同且载荷相同幂等；同键不同载荷 `409`；缺失来源键每次为独立事件，不能按内容哈希合并。
- **存储语义**：`mail_events` 为数据规范的 33 列加可检索 `text_content` 第 34 列。缺失字段兜底且记录数据质量，未研判风险是 `unknown` 而非正常。原始 JSON 仅用于受控审计，不出现在普通列表/详情。
- **输出**：`GET /api/v1/mails` 多条件列表与分页、`GET /api/v1/stats` 受限过滤统计（含附件名关键词 `attachment_name_contains`）、`GET /api/v1/mails/{event_id}` 详情；列表限制长主题/大量收件人并保留 `receiver_count`；轻量 Web 控制台调用这些 API。旧 `/v1/` EML 接口不改变。

## 2. 自然语言与研判

`POST /api/v1/nl/query` 接收 `{text, execute}`，默认仅预览。模型通过 OpenAI-compatible 或 Anthropic-compatible 协议输出**白名单过滤器**；服务端验证字段/值并编译固定、参数化 ClickHouse 模板，不能直接执行模型生成的 SQL。计划展示的 SQL 同样只能由模板生成。自然语言中的邮箱/IP/URL/MD5/11—19 位长数字先本地占位，再把占位绑定回受限过滤器；无权限或不支持的组织/部门映射必须明确拒绝，不能虚构。相对时间以 `Asia/Shanghai` 为锚点，按自然周解释。旧 `/v1/nl/query` 保持 EML 检索语义。模型超时或不可用时明确降级，基础结构化检索仍可用；未经授权不外发真实邮件；脱敏是尽力而非完整保证。

已有 Rspamd/ClamAV 与模型独立研判链路服务于旧 EML。新 JSON 事件另提供 `POST /api/v1/mails/{event_id}/analysis` 和 `GET /api/v1/mails/{event_id}/analyses`，只做按需脱敏模型意见并追加历史 `analysis_events`，不把没有 EML/附件字节的 JSON 事件伪装成杀毒扫描，也不覆盖入库时的未知风险基线。新 JSON 事件在没有明确分析证据时不被标成 `pass`/`low`。对风险等级、威胁手法、来源 IP 真实性只能基于可追溯证据输出，不以模型结论替代人工复核。

## 3. 验收口径

| 维度 | 可核验结果 |
| --- | --- |
| 接入与恢复 | 嵌套/平铺/`data` 输入、缺失/额外/畸形字段、幂等与冲突、worker 重启后队列消费；区分 202 与入库。 |
| 查询与页面 | 组合过滤、时间、正文、附件、分页、详情、未授权拒绝；首页控制台无需新依赖，token 只存内存。 |
| 模型与安全 | 双协议模拟测试、坏输出/超时/降级、白名单和注入拒绝、预览 SQL 安全、无密钥不伪装成功。 |
| 性能 | 既有 10 万 EML 导入报告只说明旧链路；新 JSON 事件需独立 10 万负载和延迟压测。 |
