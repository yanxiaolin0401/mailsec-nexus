# 部署与使用

## 1. 软件与资源

已验证 Linux / Docker Compose 部署；Python解析隔离使用 Linux `resource`。

| 软件 | 本次版本 / 固定项 |
|---|---|
| 宿主机 | Ubuntu，2 vCPU，约3.6 GiB RAM + 1.9 GiB swap（开发验证规格） |
| Docker / Compose | 29.8.1 / 5.5.1 |
| Python | 本机3.12.3；应用容器3.12.15-slim-bookworm |
| ClickHouse | 26.8.25.14 |
| Rspamd / ClamAV | 4.2.2 / 1.5.4 |
| Python依赖 | `requirements.lock`，含FastAPI0.143.0、clickhouse-connect1.10.0、httpx0.28.1 |

完整数据库、解析和病毒库并行运行建议独立提供至少 **8 GiB 内存、4核、20 GiB以上可用磁盘**作为开发起点（工程建议，不是生产容量结论）。当前小机存在swap竞争，不能据此承诺线上峰值。ClamAV官方容器文档建议为完整扫描提供至少4 GiB可用内存；更大或重载服务另行规划。[ClamAV Docker](https://docs.clamav.net/manual/Installing/Docker.html)

## 2. 本机启动

```bash
cd mailsec-smart-search
# 新环境首次复制；不得覆盖已有密钥
cp -n .env.example .env
chmod 600 .env
# 将两个不同随机值填入 CLICKHOUSE_PASSWORD、MAILSEC_API_TOKEN
sudo docker compose --profile detectors --profile malware up -d --build
sudo docker compose ps
curl http://127.0.0.1:8080/health/ready
```

`.env` 不是源代码，也不自动被 Python CLI 读取；本机运行前 `set -a; . ./.env; set +a`。Compose自动读取该文件。容器均默认只向本机发布业务/数据库/ClamAV端口；Rspamd在internal网络中，不依赖宿主机端口映射，应用通过 `rspamd:11333` 调用。不要将无认证的扫描器端口公开。

- 不启用 `detectors` / `malware` profile，基础接收检索仍可运行，分析显示检测器不可用。
- 第一次ClamAV启动需加载病毒库；`docker compose logs clamav` 检查ready。首次下载/更新可能受上游网络或频率限制，失败不能判邮件正常。
- API健康检查区分进程存活与ClickHouse可达；不代表模型/病毒库已经可用。
- 停止：`sudo docker compose stop`；恢复：同一up命令。不要使用 `down -v`，它会删除持久卷。
- `clickhouse_data`、`app_data`、`clamav_data`保留数据库/队列/病毒库，原始公开数据在项目 `data/` 只读挂载。

## 3. API 与 CLI

所有业务 API（`/v1/` 与 `/api/`）带 `X-Mailsec-Token`。未配置 token 时 fail-closed 返回 503；无效 token 返回 401。访问 `/` 可打开轻量 Web 控制台，token 仅放页面运行时内存，不写本地存储。控制台调用同一受保护 API，不另设后门。下表先列旧 EML 兼容接口；JSON 事件接口见下表后说明。

| 路由 | 作用 |
|---|---|
| `POST /v1/mail/raw` | `Content-Type: message/rfc822` + 原始邮件；202返回job_id/mail_id |
| `POST /v1/mail/upload` | multipart字段 `file`；**旧 EML 链路**同一内容去重，新 JSON 事件不按内容合并 |
| `GET /v1/jobs/{job_id}` | pending/processing/done/failed状态；202不表示已入库 |
| `POST /v1/search` / `/v1/stats` | 固定结构过滤、统计；不接受SQL |
| `GET /v1/mail/{mail_id}` | 详情；不返回本地原文路径 |
| `POST /v1/mail/{mail_id}/analysis` | 本机检测+可选模型，持久化本次结果 |
| `GET /v1/mail/{mail_id}/analyses` | 最近分析事件 |
| `POST /v1/nl/query` | `{text, execute}`；建议先 `execute:false` 预览，仅search/stats |
| `GET /v1/sop` | 预置流程清单 |
| `POST /v1/sop/{preset}` | `{candidate_limit:100, analyze:false, max_model_calls:0}`，默认只预览 |

### 新 JSON 事件接口（本轮功能闭环已验证）

| 路由 | 作用 |
| --- | --- |
| `POST /api/v2/mails` | 嵌套 JSON 主入口；也兼容平铺/`data`。`202` 仅表示 SQLite WAL FULL 队列已可靠接收；同来源键/同载荷幂等、不同载荷 `409`。 |
| `GET /api/v2/jobs/{job_id}` | 查看 JSON 事件 pending/retry/done/failed 等队列状态；使用接收响应中的 `jobId`。 |
| `GET /api/v1/mails` | 事件多条件列表，支持 `q`、`account`、`riskLevel`、`riskVerdict`、`senderIp`、`attachmentMd5`、`attachment_name_contains`、`url`、`startTime`、`endTime`、`limit`、`offset`；邮箱按小写规范化匹配。列表主题最多 512 字符、收件人最多显示前 20 个并返回 `receiver_count`，完整数据在详情。 |
| `GET /api/v1/stats` | 使用与事件列表相同的受限过滤参数返回总量；不接受 SQL。 |
| `GET /api/v1/mails/{event_id}` | 事件详情，不公开原始 JSON 审计载荷。 |
| `POST /api/v1/mails/{event_id}/analysis` | 按需生成脱敏模型意见，追加到 `analysis_events`；无附件字节，不运行/冒充 EML 杀毒扫描。 |
| `GET /api/v1/mails/{event_id}/analyses` | 查看该事件的历史模型意见与限制说明。 |
| `POST /api/v1/nl/query` | `{text, execute}`；`execute` 默认 `false`。返回白名单过滤计划，执行时由固定参数化模板查询。 |

完整输入和示例见[嵌套 JSON 接入与字段映射](detail/嵌套JSON接入与字段映射.md)。JSON 列表只在 worker 写入 ClickHouse 后可见；不能把接入 202 当作查询立即命中。新事件未知风险保持 `unknown`。旧 `/v1/nl/query` 仍查询 EML `mail_records`；CLI `mailsec query` / `mailsec ask` 默认查询新 JSON 事件，显式加 `--legacy-eml` 才查旧 EML。新事件 NL 的邮箱/IP/URL/MD5/11—19 位长数字先在本地占位再绑定受限过滤器；这种脱敏仅为尽力处理，不能保证姓名等自由文本敏感信息全被遮盖，外发仍须授权开关；不支持的部门组织关系直接拒绝。自然周以 `Asia/Shanghai` 为准。预览展示的 SQL 不是模型生成文本，而是服务端固定模板编译结果。模型协议模拟测试不等于真实联通。

**旧 EML** 过滤条件（不适用于 `/api/v1/mails`）：`from_time/to_time`（带时区ISO时间，针对发信时间）、`sender/sender_domain/recipient`、`subject_contains/body_contains`、`has_attachment/attachment_suffix`、`limit`（1—200）、`offset`（0—10000）。文本contains是大小写不敏感子串，不是语义向量检索。没有可信Date的邮件不命中日期条件。

```bash
set -a; . ./.env; set +a
.venv/bin/mailsec query '{"attachment_name_contains":"发票","limit":10}'
.venv/bin/mailsec query --legacy-eml '{"subject_contains":"invoice","has_attachment":true,"limit":10}'
.venv/bin/mailsec ask '统计包含发票主题的邮件数量'        # 默认新 JSON 事件，先预览
.venv/bin/mailsec ask '统计包含发票主题的邮件数量' --execute
.venv/bin/mailsec ask --legacy-eml '统计包含发票主题的邮件数量' # 旧 EML 链路
```

旧 EML 自然语言中的邮箱/URL 等敏感字段仍会 422 拒绝外发；新事件会先对邮箱/IP/URL/MD5/长数字做本地占位并安全绑定，但不能保证自由文本完全脱敏。查具体地址也可用本地结构化查询。read-only不等于无需人工核验：模型可能理解错条件，查看plan后再执行。

## 4. 第三方模型

在 `.env` 配置（不提交真实密钥）。新事件按需分析也需要同一授权与配置；没有真实密钥时返回不可用/未知，不写出虚假的正常结论：

```dotenv
MAILSEC_LLM_PROVIDER=openai
MAILSEC_LLM_BASE_URL=https://YOUR_PROVIDER/v1
MAILSEC_LLM_MODEL=YOUR_MODEL_ID
MAILSEC_LLM_API_KEY=YOUR_SECRET
MAILSEC_LLM_EXTERNAL_AUTHORIZED=true
```

另支持 `MAILSEC_LLM_PROVIDER=anthropic`，调用 `/v1/messages` 格式。base包含`/v1`，不要重复填写 `/chat/completions` 或 `/messages`。第三方需实际支持所选协议，不能仅凭域名推断兼容。未授权不要打开开关；只配置key不会自动批准外发。

```bash
set -a; . ./.env; set +a
.venv/bin/python scripts/smoke_model.py    # 只发合成文本，不读真实语料
sudo docker compose up -d api worker     # 重新创建以加载配置
```

OpenAI-compatible使用Bearer，Anthropic-compatible使用x-api-key和anthropic-version；HTTPS，无自动跟随重定向，有限重试429/5xx，响应16 KiB上限。调用记录包含model、脱敏版本、输入hash与证据字段。真实endpoint/key尚未提供时，NL接口明确503，基础检索不受影响。

## 5. 数据导入和评测

下载/清单/许可证见 [data/README.md](../data/README.md)。下载完成后压缩包自动安全清理，不重复保留。

```bash
set -a; . ./.env; set +a
.venv/bin/mailsec import-directory data/raw/enron/maildir --source enron \
  --limit 100000 --batch-size 250 --report docs/reports/enron-import-100k.json
.venv/bin/python scripts/benchmark.py --output docs/reports/query-benchmark.json
.venv/bin/python scripts/smoke_http.py
.venv/bin/python -m pytest -q
.venv/bin/pip check
```

上述公开语料导入、去重与查询基准均针对旧 EML 链路，不能当作 10 万新 JSON 事件压测证据。

导入limit指遍历文件数，不保证等量独立内容；报告须区分seen/duplicates/inserted。checkpoint在`var/imports/`；只有批写成功才提交；数据库目标改变时使用新的 `MAILSEC_DATA_DIR`，不能复用旧checkpoint。原文在 `data/raw`，不重复拷入队列。

本机检测评测必须在可访问internal Rspamd的网络运行；以下不调用LLM：

```bash
mkdir -p var/evaluation docs/reports
sudo docker compose run --rm --no-deps --user "$(id -u):$(id -g)" \
  -v "$PWD/scripts:/scripts:ro" -v "$PWD/var/evaluation:/evaluation" \
  -v "$PWD/docs/reports:/reports" api python /scripts/evaluate_detectors.py \
  --data-dir /datasets --checkpoint /evaluation/results.sqlite3 \
  --output /reports/detection-baseline.json --limit-per-class 500
```

`--limit-per-class`仅控制单类最大数，按来源清单顺序选取；不是随机代表性样本或无偏准确率估计。调高可利用全部有标签语料，checkpoint可续跑；改变检测器版本/配置时使用新checkpoint，不混用旧结果。

## 6. 运维注意

备份原始邮件、清单、ClickHouse数据和spool/checkpoint的一致快照，先暂停写入。恢复后核对SHA及入库量；清库和删原文都是破坏性操作。当前未内建定时备份、生产监控/RBAC/TLS、HA 或生产级多租户授权；开放给他人前需部署TLS反向代理和用户权限体系。

服务 CLI 以 INFO 级别输出 NL 工具审计日志（输入 hash、工具名和执行状态，不含查询原文）；普通 HTTP access log 已关闭，避免查询邮箱/IP进入 URL 日志。需要专门的授权审计与日志留存方案；成功日志须由部署日志系统保留。

十万封压测后补充：本机正文contains查询采用FIFO单槽（等待上限5秒）避免并发挤爆数据库；最新并发4正文p95约3.99秒。扩大实例或优化索引前，不承诺所有查询亚秒级。
