# 本轮优化实施计划

> 状态：本轮功能闭环已完成并验证；企业/容量/真实模型与生产安全验收另列后续。本文保留行为锁与验收边界，证据见[验证记录](验证记录.md)。实施者负责文档与代码，主任务负责人独立复核。

## 依据与优先级

1. 本轮用户明确要求：前置 HTTP JSON 接收、清洗与持久化，在其上检索和以自然语言查询；支持 OpenAI-compatible 与 Anthropic-compatible 模型协议。
2. [研发任务与推进计划](detail/基于大模型的邮件数据分析与智能检索系统_研发任务与推进计划.md)是当前研发主线；[输入输出与数据规范](detail/邮件离线分析系统_输入输出与数据规范.md)是字段及 API 契约。二者的平铺 JSON 例子由[嵌套 JSON 接入与字段映射](detail/嵌套JSON接入与字段映射.md)补充；原始来源文件保留，主研发计划与规范 Markdown 中会就地修订已冲突的实施语义。
3. [测试样例工作簿](detail/邮件离线分析_测试样例_demo.xlsx)用于核对真实输入层级与字段；[开题汇报](detail/开题汇报_基于大模型的邮件数据分析与智能检索系统.html)用于课题背景，不能覆盖更新的接口约定。

## 清理范围与行为锁

- 保留并核验旧 EML 接入（`/v1/mail/raw`、`/v1/mail/upload`）、`mail_records` 和既有历史评测报告；不把内容哈希去重当作 JSON 投递事件的去重规则。
- 新增 JSON 事件入口 `POST /api/v2/mails`：主格式为 `{sourceSystemId,sourceEventId,eventTime,mail:{...}}`，兼容规范的平铺业务字段及 `data` 对象；只映射显式已知路径，不递归猜测。未知业务字段不参与映射，原请求仅在受控审计存储中保留，查询接口不暴露。
- 本地持久队列成功写入后才能回 `202 Accepted`；这表示可靠接收，不表示 ClickHouse 已落库。相同来源系统/来源事件 ID 且相同载荷幂等；同键不同载荷冲突 `409`；来源 ID 缺失的投递各自成为事件。
- ClickHouse `mail_events` 保持规范 33 列并增加 `text_content` 第 34 列；接收器/worker 与 EML 处理并存。未分析邮件风险状态为未知，不能以 `pass`/`low` 伪称安全。
- 实现事件多条件列表、详情和受限自然语言查询；支持按附件名称关键词检索。模型只产出白名单过滤条件，SQL 由服务端固定参数化模板编译。新事件自然语言默认不执行查询，计划中的 SQL 也只来自安全模板；CLI 默认新事件，`--legacy-eml` 指向旧链路。
- 首页提供无新依赖的轻量 Web 控制台；API token 只保存在页面内存。详情可按需调用脱敏模型，并将意见追加 `analysis_events`；不把 JSON 当 EML 扫毒、不覆盖 `mail_events` 未研判风险。保留旧 EML 自然语言接口语义。
