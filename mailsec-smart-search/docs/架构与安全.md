# 架构与安全

## 数据流

主链路：`HTTP JSON → token/限长 → SQLite WAL FULL 本地事件队列 → worker 清洗/批写 mail_events → 固定参数化模板检索 → Web`。`202` 只确认本地队列持久接收，ClickHouse 写入异步完成。

兼容链路：`HTTP EML → 鉴权/限长 → durable spool → 独立解析进程 → 批写 mail_records → 固定模板检索`。两条链路共用 worker 调度但存储、事件标识和去重规则不同；EML 内容哈希去重不能用作新 JSON 投递事件去重。

公开语料另经 `data/raw → 可终止解析子进程 → 批写 → SQLite checkpoint`；以原文 SHA-256 去重，原文引用可跨容器解析。旧 EML ClickHouse 表由 `src/mailsec_smart_search/schema.sql` 定义，使用 ReplacingMergeTree，查询 FINAL 提供逻辑去重，不把重试重复行计入独立样本数。

新 `mail_events` 为规范 33 列加 `text_content` 第 34 列；未知风险显式 `unknown`，不是 `pass`/`low`。事件按需模型意见追加到 `analysis_events`，不修改 `mail_events` 风险基线；JSON 事件缺少 EML/附件字节，不能宣称经过 Rspamd/ClamAV 实际扫描。来源元数据、邮件头与源 IP 属于上游声明；未知字段不参与映射，原始 JSON 仅存受控审计字段，不从普通查询暴露。

分析流程：`原文路径/哈希校验 → 本机 Rspamd + ClamAV → 授权脱敏字段的独立模型判定 → 固定融合规则 → append-only 分析事件`。模型不读取检测器结果，避免假装“独立”却被先验标签诱导。此句仅适用于旧 EML 分析；新 JSON 事件分析是独立模型意见，不与本机扫描融合。

## 安全边界

| 边界 | 控制 |
|---|---|
| 邮件输入 | Token 鉴权先于解析；EML 和新事件 JSON 均受配置的邮件大小上限约束（默认 15 MiB、配置最高 20 MiB）；multipart 额外 64 KiB；其他普通 JSON 请求总体 64 KiB；接入并发 8 |
| 解析 | 原文不执行；HTML 不浏览；URL 不访问；子进程超时可终止；导入解析进程地址空间上限 512 MiB |
| 存储 | 参数绑定、固定 SQL、表名校验；只读 API 不接收 SQL/DSL；查询 5s/512 MiB/1000万扫描行限制；事件列表主题只返回前 512 字符、收件人前 20 个和 `receiver_count`，详情单独读取 |
| 证据 | 限于 spool/datasets 根内，拒绝越界引用，读取后 SHA-256 校验 |
| 模型外发 | 默认关闭 `MAILSEC_LLM_EXTERNAL_AUTHORIZED`；需要有效 HTTPS endpoint/model/key；白名单字段、邮箱/URL/IP/电话/长token遮蔽；不发原始 EML、附件内容或本地路径 |
| 自然语言 | 旧 EML 接口只允许 search/stats；新事件接口只接受白名单过滤器，邮箱/IP/URL/MD5/11—19 位长数字本地占位回填，禁止模型 SQL 直通、shell 或写入。部门组织映射无数据时拒绝；相对时间按上海自然周解释；占位脱敏尽力而非完整保证，外发需显式授权 |
| 资源 | 查询并发16、正文contains在单实例内单槽排队（最长等待5秒）、分析并发2、模型调用预算；SOP最多10封分析、30秒软预算；超时与部分完成明确标记 |
| 扫描 | Rspamd无外网内部网络且禁用在线DNS/黑名单/模型模块；ClamAV仅私网，使用病毒库更新；两者均不执行附件 |

脱敏是尽力处理，**不保证自由文本中所有人名、地址、商业秘密都被识别**。开启授权开关意味着操作者已批准该实例所处理语料的允许字段外发；混入未授权数据前必须关闭开关或分离实例。API Key 只能存 `.env`/密钥管理，不能放截图、请求示例或 Git。

## 判定与可信度

- 只有明确 ClamAV 恶意签名可以直接提升为 malicious；非签名“恶意”线索输出 suspicious 并要求复核。
- 全部三个引擎成功且均正常、解析证据完整时才返回 clean；失败/缺失不能投票为正常。冲突及不足保留各自证据和错误状态。
- Received-SPF 为**邮件中声称的结果**，不是本系统重新验证的 SPF。历史邮件不能用当前 DNS 状态倒推当时真实身份。
- Rspamd 首版为离线规则基线，禁用未训练的 Bayes/Redis及在线信誉模块；不声称达到完整生产Rspamd的效果。最有效算法须同一无泄漏留出集比较，当前不作普适最优承诺。
- 三个 SOP：发票/付款线索、未验证 SPF fail 声称、双后缀可执行附件；只检查有限最近窗口，不是全库全覆盖。SPF声称不等于已实现“发信域仿冒”确证。

## 已知限制

单主机、单 worker 队列；新事件队列使用 SQLite WAL FULL、本地私有文件权限。默认约 5 GiB 队列空间预算，对 SQLite 数据库/WAL/SHM 的物理高水位和低磁盘余量拒绝新写；至少预留 1 MiB 元数据空间，不删除历史幂等回执。失败日志仅记异常类型及数据库错误码，不写敏感原文。历史回执归档与幂等保留期尚需生产设计。普通 HTTP access log 关闭，避免带邮箱/IP的查询参数进入 URL 日志；不等于完整审计体系。未实现多租户/RBAC、TLS网关、动态沙箱、SMTP或生产备份恢复编排。只读检索与数据维护共用数据库凭据，后续生产部署应拆分权限。队列文件和导入checkpoint需与数据库一起备份；不得一边清库一边保留旧checkpoint。全量检索随积累增长，当前分区/排序不能保证任意规模秒级。旧 EML 跨来源相同原文按hash合并，完整来源/标签另在数据清单保存；新 JSON 同内容不同投递需分别保留。
