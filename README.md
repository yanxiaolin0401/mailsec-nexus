# 邮件安全智能分析与溯源平台（MailSec Nexus）

本项目面向企业安全运营，目标是具备前后端分离、租户/项目与用户隔离、具有最高操作及全平台数据读写权的管理员后台、用户租户/管理员双模式登录、证据与案件闭环、可评测算法及可运维交付的邮件智能检测产品。三个算法模块独立开发/测试/发布，由统一平台串联；产品目标不等于当前已全部实现。

## 目录

| 目录 | 职责 | 对应课题 |
| --- | --- | --- |
| `mailsec-header-parser/` | 异构邮件头解析、伪造线索与流向研判 | 课题 6 |
| `mailsec-smart-search/` | HTTP 邮件接收、批量导入、ClickHouse 检索与智能安全分析 | 课题 5 |
| `mailsec-threat-trace/` | 基于告警的行为归因、候选检测规则与回测 | 课题 4 |
| `mailsec-platform/` | React + TypeScript 网页平台、FastAPI 编排接口、集成部署 | 综合平台 |
| `contracts/` | 跨模块数据与接口契约 | 共享边界 |
| `tests/` | 跨模块端到端验收 | 综合验收 |

## 工作原则

- 各模块拥有自己的源码、测试和文档；平台不直接实现模块算法。
- 模块间通过契约化 API、批处理数据及分析结果协作，不直接读写彼此的业务表。
- 原始邮件是证据，解析结果和模型结论是可追溯、可重算的衍生数据。
- 大模型生成的查询、解析代码和规则都是候选产物；经过校验、测试和审核后才能进入执行链路。
- 开发顺序固定为 **smart-search → header-parser → threat-trace**。平台身份、正式页面、测试和部署随阶段建设；smart-search独立交付仍不以另外两个课题为前置条件。

`mailsec-smart-search` 已提供可运行的独立服务、公开数据与验证工具，见[模块说明](mailsec-smart-search/README.md)。其他模块仍保持各自开发状态；真实第三方模型联通与企业验收不能由模拟测试替代。

顶层决策见 [`docs/项目目标与顶层约束.md`](docs/项目目标与顶层约束.md)；待索取的数据、技术环境和协议材料见 [`docs/资源需求与待确认事项.md`](docs/资源需求与待确认事项.md)。
